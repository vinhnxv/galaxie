# ADK recipes in the browser

Choose a recipe in one Vite page. The page offers the financial advisor on ADK JavaScript and ADK Go, the LLM auditor on ADK Python, and the small-business loan pipeline on ADK Python. It shows checked streamed text and selected model destinations; the verbatim upstream financial disclaimer appears above financial output. Mock mode uses deterministic scripted models and requires no model download. Default mode offers the pinned local ONNX model below; its real-model behavior remains unmeasured.

| Recipe | Browser shape | Rewrite details |
| --- | --- | --- |
| Financial advisor (JavaScript) | Data, trading, execution and risk specialists in a fixed sequence | Replace the conversational coordinator and `AgentTool` specialists with `SequentialAgent`; replace Google Search with fixture search; [financial rewrite deltas](ATTRIBUTION.md#financial-advisor-rewrite-deltas) |
| Financial advisor (Go) | The same four specialists and output keys in a verified wasm Worker | Use galaxie's Go constructors and the same condensed prompts, disclaimer and fixture search; [financial rewrite deltas](ATTRIBUTION.md#financial-advisor-rewrite-deltas) |
| LLM auditor (Python) | Critic then reviser | Keep the sequence, replace search, and omit grounding-reference and end-of-edit callbacks; [Python rewrite deltas](ATTRIBUTION.md#python-auditor-and-loan-rewrite-deltas) |
| Small-business loan (Python) | Extraction, underwriting, pricing and decision, with approval in the final child | Replace the coordinator and cloud storage with capabilities over fixtures; omit planner, judge and cloud model setup; [Python rewrite deltas](ATTRIBUTION.md#python-auditor-and-loan-rewrite-deltas) |

All companies, applicants, application documents and market bulletins are invented. There is no real personal data or real news. Outputs are not financial advice and must not be used for real lending decisions. galaxie is not affiliated with or endorsed by Google. The page retains the upstream financial disclaimer verbatim; see [attribution](ATTRIBUTION.md) and [ADR-0025](../../docs/adr/0025-adk-recipes-demo.md).

From the repository root:

```sh
pnpm install --frozen-lockfile
pnpm --filter @galaxie/example-adk-recipes dev:mock
pnpm --filter @galaxie/example-adk-recipes exec vite build --mode mock
pnpm --filter @galaxie/example-adk-recipes build
pnpm --filter @galaxie/example-adk-recipes preview
pnpm exec vitest run examples/adk-recipes
```

Use the built preview for either mode so the strict script policy needs no development-client exception. Mock mode retains the exact same-origin-only CSP. Default mode changes only `connect-src`, adding `https://huggingface.co` for the record's immutable resolve URLs and `https://us.aws.cdn.hf.co` for Hugging Face's weight redirects (the host observed from the maintainer machine on 2026-11-05; it may differ by region or over time, and no real download has confirmed it, so a blocked download means this list needs updating). There are no wildcard sources or GitHub download hosts. The Vite server shares the header with the dedicated inference Worker's response; production hosting must serve that header too. Both modes retain `script-src 'self' 'wasm-unsafe-eval'`, `worker-src 'self'`, `require-trusted-types-for 'script'` and `trusted-types default`, with no `unsafe-eval`. The existing exact-URL Trusted Types validator additionally permits the bundled same-origin ONNX module Worker; it still refuses arbitrary, blob and off-origin Worker URLs. All tests, including the default-bundle browser probe, serve the original same-origin-only header and block external requests. The ADK runtime setup disables span content capture and uses jitless Zod; the Vite alias selects ADK's pinned web bundle. Only recipe authoring files may import the ADK root package.

## Pinned local model

| Model | Immutable revision | License | Configuration | Text-only download |
| --- | --- | --- | --- | --- |
| `onnx-community/Qwen3.5-0.8B-ONNX-OPT` | `9a4c21d8f724176b0a7edaaed36303044451886e` | Apache-2.0 | q4, WebGPU, context window 4096, XML tool calls | 666 MB (666,378,110 bytes) |

The [reviewed record](src/host/model-records/qwen3.5-0.8b-onnx-opt-q4.json) is unchanged from the maintainer's pin output: nine files, including the text-only split decoder and embeddings, with per-file sizes and SHA-256 digests. No weights are redistributed or committed. The weights come from Hugging Face on first use only after the user accepts the download prompt showing its size and origin. The Worker verifies sizes and hashes before use and stores verified files in Cache Storage. A cached load re-verifies those bytes without download permission; integrity failure does not silently fetch replacements. Storage eviction can require another consented download.

`models.ts` validates the record with `parseModelRecord` and lists ONNX first for each eligible recipe role, with `in-browser` destination and zero pricing. A missing or invalid record offers no ONNX provider; a record without a declared tool format is omitted for tool-using roles. Mock mode continues to use only its recipe's scripted providers. The router prefers a ready in-browser alternative before asking to download. Declining a download may select a later ordered provider before dispatch; this host configures no default alternative and shows an unavailable message for absent WebGPU/storage or a declined download. After dispatch there is no fallback, including on engine or Worker failure. Start over creates a fresh document and handle. The provider bundles Transformers.js 4.3.2 through its optional peer and same-origin ONNX Runtime assets; the example imports no Transformers.js library directly.

The pin probe reports that Qwen3.5's template mentions `enable_thinking`. The provider passes `enable_thinking` only when the record declares `template.enableThinking`. This unchanged record declares no override, so the template's default applies; thinking mode has not been disabled here. `TransformersChatModel` parses tool markup when tools are offered but does not strip `<think>` text. Any such emitted text remains ordinary checked reply text, consumes the generation budget and can appear in the output. The provider rejects a request whose prompt plus output limit exceeds the 4096-token context window, and later agents receive earlier replies in their prompt. In a first hands-on run of the financial recipe on the maintainer's device (one run, one device, Chrome with WebGPU), replies of the provider's default 1024 tokens gave the fourth model call a 4007-token prompt and the run failed with the fixed `invalid` error. This example therefore limits every reply to 384 tokens, both for generation and for the router's reservation. Replies can end mid-sentence, and `<think>` text or an unfinished tool call can use up the same limit. With the limit, that single financial run completed with a peak prompt of 2994 tokens. The loan and auditor recipes were not run with the real model; their worst-case prompts are estimated, not measured, at about 3400 and 3300 tokens including the reply limit.

`LiquidAI/LFM3-1.7B-ONNX` remains unpinned: its q4 data file is about 1.63 GB, above the record's 1 GiB per-file limit. There is no record, provider entry or result for it. The maintainer-device demonstration is in the [real-model record](../../docs/adk-recipes-real-model-record.md). Apart from the single run described above, no real-model result, tool reliability, answer quality, download performance or device metric is claimed.

| Capability | Input | Result and policy |
| --- | --- | --- |
| `market.search@1` | Non-empty query, at most 160 characters | Case-insensitive substring search over synthetic bulletins; `public`, explicitly untrusted tool output |
| `loan.documents@1` | Synthetic application ID | Fixture documents; `private-user` |
| `loan.business@1` | Synthetic application ID | Fixture internal business data; `private-user` |
| `loan.price@1` | Integer credit score 300–850, amount 1000–250000 demo dollars, term 12–60 months | Pure synthetic annual-rate tiers: 300–649 review at 12.5%, 650–749 standard at 9.5%, 750–850 preferred at 6.5%; `private-user`. Amount and term are validated context, not inputs to the tier threshold |
| `loan.finalize@1` | Application ID and `approved` or `denied` | Host-memory decision record; `private-user`, write, broker confirmation required, retry `none` |

Collections contain at most five items and at most 4096 UTF-8 bytes including the JSON envelope. Excess whole items are omitted with `truncated: true` and `[truncated]`. The oversized synthetic bulletin exercises the byte limit. Unknown application reads return the fixed empty `not_found` envelope. Invalid arguments produce a fixed `invalid` error. Principal scope comes from trusted host context, not arguments; bindings reject other principals. There is no lending backend. Direct invocation of a host binding bypasses broker approval; agent callers must use the broker. The loan page composes durable checkpoints and recovery to journal confirmed writes; the fixture binding's decision records remain host-memory data.

Pricing is authored synthetic fixture logic. Upstream pricing was inspected only for licenses and notices, so no claim is made that these tiers reproduce its implementation.

The financial recipe exports `financialDefinition` and `financialAgent` from `src/recipes/financial/agent.ts`. Register `createAdkAdapter()` from `@galaxie/adapter-adk`, bind `market.search@1` from `createHostCapabilities`, and pass the agent factory to `runtime.create`. Before evaluating ADK's browser bundle, run the host's `adk-env.ts` setup. `createFinancialMockModels()` in `src/recipes/financial/script.ts` supplies scripted providers and routes for two sample prompts, with all preferences in the initial prompt. The four specialists write `market_data_analysis_output`, `proposed_trading_strategies_output`, `execution_plan_output` and `final_risk_assessment_output`; the last value is the run output. Trading, execution and risk prompts request the verbatim disclaimer, and every successful scripted final reply ends with it. Arbitrary model output is not verified here.

The financial tests cover state interpolation, ordered checked `messages` chunks, search `updates`, empty fixture results, a blocked output chunk, a step budget of one and an instruction-bearing search result through the real broker, on Node and headless Chromium. Chromium uses the unchanged strict CSP and Trusted Types policy, records policy violations and rejects external requests. These are scripted orchestration checks with no real model; they do not establish financial quality or model resistance to prompt injection. See the [rewrite deltas](ATTRIBUTION.md#financial-advisor-rewrite-deltas) for what was preserved and dropped.

The Python Vite plugin selects only ADK wheels from the existing inventory and this example's `agent_py` sources, excluding source lint tests. It requires local wheels, verifies their hashes and lengths, and uses the existing same-origin Pyodide runtime. It omits the lane if prerequisites are absent. The Go plugin builds `go/recipes/financial/main` when Go is installed, using the existing locked build helper with module downloads disabled. It verifies the glue and emits same-origin wasm assets with length/SHA-256 metadata for adapter preparation. With Go absent, the build succeeds and reports Go assets unavailable. With Go present, the locked toolchain and cached modules must be available. The registry disables Python entries when verified wheels are absent and the Go entry when its wasm was not built. The Vite build still succeeds without either lane. Selecting JavaScript does no Python or Go runtime work.

## Go financial recipe and rewrite deltas

The [Go recipe](../../go/recipes/financial/agent.go) uses `galaxie.Model`, `galaxie.LlmAgent`, `galaxie.SequentialAgent` and `galaxie.CapabilityTool`. Its `main/main.go` registers the `financial` entry with `galaxie.ServeWith`. The upstream conversational coordinator and its `AgentTool` specialists become the same fixed data, trading, execution and risk sequence as JavaScript; the same output keys carry state between specialists. Google Search becomes the host's bounded synthetic `market.search@1` capability. Prompts are Go string constants with the exact condensed JavaScript text and verbatim disclaimer; the financial rewrite deltas in [attribution](ATTRIBUTION.md#financial-advisor-rewrite-deltas) apply to both versions. No cloud model, environment setup, web launcher or deployment configuration is retained.

Build the wasm from the repository root with `node scripts/build-go-wasm.ts ./recipes/financial/main`. Register `createGoAdapter()` from `@galaxie/adapter-go` with a host-owned Worker that imports the verified `wasm_exec.js` before the adapter Worker entry. Pass its same-origin wasm descriptor to `financialGoAgent(wasm)` and use `financialGoDefinition` from `src/recipes/financial-go/definition.ts`, the shared fixture binding and `createFinancialMockModels()`. The definition shares the JavaScript input, roles and capability contract without loading its ADK agent factory. See the [adapter guide](../../packages/adapter-go/README.md#hosting) for Worker wiring and limits.

Native Go tests check specialist order, routed roles, interpolated state and offered tools. The Node test runs the actual wasm and compares the final reply and all four output-key values with JavaScript for fixture-backed and empty searches, checks growing streamed output through the safety hook, and enforces the reference module's 48 MiB raw wasm ceiling. It uses the existing Go gate message when the toolchain is absent. These are scripted orchestration checks with no real model or device performance claim; the picker runs the same Go recipe in a dedicated Worker. The Go dependency lock is unchanged.

## Python recipes and rewrite deltas

Register `createPyodideAdapter({ framework: 'adk', ...options })` with same-origin runtime and wheel URLs and a host-owned Worker. `auditorAgent(baseUrl)` and `loanAgent(baseUrl)` in their recipe `definition.ts` modules declare the complete source file lists; `baseUrl` is the same-origin `/python/agent/` directory emitted by the existing Python asset plugin. Definitions and scripted models live under `src/recipes/llm-auditor` and `src/recipes/loan`. Every Python factory builds fresh agents; the adapter owns runners and sessions. No helper wheel is changed or rebuilt.

The auditor retains the upstream critic-then-reviser `SequentialAgent`. `search_fixture` calls `market.search@1` instead of Google Search. The condensed prompts retain claim-level verdicts, justifications and an overall assessment, add explicit state keys for critic findings and the revised answer, and limit verification to invented bulletins. The grounding-reference callback is dropped because there is no Gemini grounding metadata; the critic cites fixture bulletin IDs instead. The end-of-edit callback is dropped separately; the reviser is instructed to emit only the answer without `---END-OF-EDIT---`, with no callback that strips it. `google.genai` imports, environment model selection and cloud configuration are removed. Missing evidence and denied search are unverifiable and leave the original answer unchanged. The default sample is fixture-backed. The page reports free-text questions outside its exact scripted fixture as unverifiable without starting an executor; it makes no factual inference about them. The financial page follows the same rule.

The loan coordinator and its `AgentTool` specialists become a fixed `SequentialAgent`: extraction, underwriting, pricing, then decision, retaining the four upstream specialist names and output keys. Only the last child can pause. Host capabilities replace cloud document loading, direct search and database access, including any BigQuery-style integration; the pinned loan recipe's internal lookup is itself a mock record dictionary, not a BigQuery query. The rewrite reads synthetic text documents through `loan.documents@1` and business records through `loan.business@1`. It drops GCS/PDF injection, Firestore status and state callbacks, the initial process-status tool, coordinator conversation, LLM judge gate, planner, `App`, Gemini retry/thinking configuration and all `google.genai` imports. The host owns checkpoint and submission recovery. Missing schema fields such as EIN, address, years in business and decision-letter references are omitted, along with upstream output models and eligibility-rule loading. Reports are text state values and do not establish a lending policy.

Pricing calls `loan.price@1` through `capability_tool`; there is no Python pricing function. Its credit-score tiers are synthetic, with no claim of parity with upstream pricing. Monthly payments and total interest are omitted. The decision tool calls `loan.finalize@1` with confirmation required. `loanInteractionBindings` supplies a headless approval contract; the host's `loanApprovalSummary` projects company, applicant, annual revenue and proposed write from trusted fixtures and pending arguments, without raw documents. The shown decision must come only from that pending confirmation or the host's finalize receipt. `loanOutcome` accepts no model text: a text-only decision completes undecided, even when it says approved. Denying confirmation completes without a write.

The finalize binding retains its independent broker confirmation. Hosts must configure `CreateOptions.confirmations` for `loan.finalize@1` and obtain explicit approval for the exact arguments; the page presents a separate host-rendered **Finalize** confirmation after **Approve** on the Python interaction. **Deny** continues without finalization. The test probe can match the broker gate to its explicit approved interaction; the page obtains a second explicit human action for the write. Broker confirmations are not persisted. Supply `loanOutcome` with the selected application ID and only the current session's host receipts; unrelated application receipts cannot finalize it, and a current pending request takes precedence. With scoped byte checkpoints and `saver.recovery`, reload restores the same Python pending interaction. A succeeded write receipt can replay after Worker loss without another invocation; retry `none` preserves the existing unknown-outcome rules. This does not create a durable lending backend or guarantee exactly-once external effects. Keep checkpoints and recovery records on-device under the app/principal scope and use one active owner. Core returns `stale` for mismatched interaction IDs, `invalid` for malformed approval payloads and `duplicate` for already accepted submissions.

## Page lifecycle and loan approval

Each page load constructs only the chosen executor, on **Run** or when restoring a saved loan pause. There is one active recipe per document. Switching the picker aborts the run and awaits disposal before navigating to a fresh document. **Start over** clears the current session and reloads the page. Financial and auditor sample questions are scripted fixture defaults; free-text outside those fixtures reports **Unverifiable**. Model text renders as React text only. The demonstration output-safety hook allows routed output; the browser test also injects a blocking hook to check that blocked text is not displayed. This hook does not assess financial content.

The loan surface uses `loanInteractionBindings` through the React registry and derives its summary with `loanApprovalSummary`. The outcome display uses only `loanOutcome` with pending arguments or the current application's `loan.finalize@1` receipt. The decision agent's model prose is omitted from the output display. Without a finalize call, completion remains **Undecided**, even when the model says approved. **Approve** opens the separate broker confirmation; **Finalize** records the synthetic decision in host memory. **Deny** makes no finalize write.

Loan checkpoints and the recovery journal share the app/principal-scoped IndexedDB saver. A sessionStorage reference identifies this tab's paused session. The host composes a fenced Web Lock with disposal so another active owner cannot write the same app's state. Reload restores the pending approval; the in-page broker confirmation asks again because it is not persisted. **Start over** settles the run before deleting its checkpoints and recovery records. Other recipes and the visible answer text are not restored. Browser eviction loses the session. This is not a durable lending backend, cross-device recovery or an unknown-outcome reconciliation service.

## Evidence and limits

[Model wiring tests](test/models.test.ts) use a tiny synthetic record and the provider's fake runtime through the real Worker protocol, ADK adapter, router and broker. They check consented download, missing/invalid records, tool-format eligibility, cached-before-download ordering, refusal before dispatch, failure after dispatch, missing WebGPU, thinking-text handling and every committed file digest. They download no real weights. The committed model license is documented beside its revision above.

[Rendered host tests](test/host-browser.node.test.ts) cover the JavaScript and optional Go picker runs, disclaimer ordering, model destinations, checked output, unknown questions and abort-before-switch behavior. [Python host tests](test/adk-python-host-browser.node.test.ts) cover the auditor, loan approval and denial, pause reload, Start over and text-only undecided completion. Both use headless Chromium, record CSP/Trusted Types violations and reject requests outside the preview origin. These are scripted model tests; there is no real-model, real-device, answer-quality, financial-quality or lending-quality result. No model download, latency distribution or device metric is claimed.

Python execution tests use the existing verified-wheel gate and authored mock replies, with no real model. Their filenames contain `adk-python` for the Python CI shard. Node and headless Chromium ran against the cached Pyodide wheels on 2026-11-05: auditor correction, empty/denied search and cancellation; loan approval, denial, text-only completion, stale/invalid submissions, fresh-Worker restore and receipt replay; and Chromium reload through IndexedDB with same-origin runtime assets under the unchanged CSP and Trusted Types policy. The browser probe runs `adk-env.ts` before schema-bearing imports so Zod never probes `Function` under Trusted Types. The pinned native CPython environment still cannot run pytest on this machine because `libssl.3` is missing; the syntax-only lint aid was run separately without those dependencies. Missing wheel inventories skip locally and fail in CI under the existing gate. Pyright includes the new sources and the Python checks job collects their lint-aid test. No ruff configuration exists in this repository. No real-model result or answer-quality measurement is claimed.
