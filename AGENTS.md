# AGENTS.md

Guidance for coding agents (Claude Code, Codex and others) working in this repository.

## Project status

galaxie has its first four M1 runtime slices: `packages/core` provides lifecycle, identity, cancellation, replayable in-memory events, allowlisted OpenTelemetry spans, a capability broker with grants and validation, sticky data labels and argument shapes, and finite budgets for steps, tool calls, wall clock, payloads, tokens and cost. Its model router enforces ordered per-role providers, destination classes, labels, shared consent and per-call credentials, and publishes selected routes in snapshots. `packages/core` also owns run segments and an in-memory accepted/consumed submission inbox with checkpoint-confirmed, deduplicated dispatch. Its M1 exit controls check interaction URL origins before pending state and gate opt-in development trace text by live run labels and the declared trace destination. `packages/adapter-langgraph` routes native chat calls, reads pending interactions from checkpoints and resumes them by interrupt ID; `requestInteraction(request, config)` works after an await on Node and Chromium. Its twelve parity cases cover interrupts, subgraph re-execution and durability modes; additional Node/Chromium tests cover interaction policy, lifecycle, budgets and complete span trees. The explicit-config API list is in `tests/conformance/README.md`, beside the compatibility matrix, and system design §9 maps M1 guarantees to code and tests. The adapter installs a synchronous context shim only when no global context exists; Node hosts needing async LangChain context must initialize real `AsyncLocalStorage` before the first prepare (system design §6). Parallel interrupts, static breakpoints, ID-less interrupts and multiple requests per node remain unsupported; `packages/models` ships the deterministic mock and `@galaxie/models/webllm`, a lazy WebLLM 0.2.86 worker provider with a shared FIFO queue, reset per request, cancellation, final-only usage, `jsonSchema`, provider-level `withStructuredOutput`, a commit-pinned record with SRI, content-free progress and typed errors, and a page-side device report. Loading, streaming, cancellation and schema wiring have fake-engine coverage only on Node and Chromium; real-device verification, prefill abort latency and the cost of foregoing KV-cache reuse remain unmeasured. After worker failure or device loss the selected provider keeps failing `unavailable`, without fallback; recovery requires a new handle, model and runtime. Hosts bundle and start one worker per runtime and may declare `structured-output` for routing. SRI covers config, library and tokenizer, not weight shards; validation requires an immutable weight revision. Only the worker needs the download hosts and WASM CSP directives (system design §8.4). `@galaxie/models/builtin-ai` adds a page-only Chrome Prompt API model with one session per call, streaming, cancellation and provider-level schema output through `responseConstraint` with the schema omitted from input. Configure input/output languages and register it with destination `in-browser`, zero pricing, features `['streaming', 'cancellation', 'structured-output']` and the role's languages. Calls require `available` and never download; hosts use `checkBuiltInAI` to probe and `prepareBuiltInAI` from an intentional download click, with content-free progress. Typed reasons distinguish `no_api`, `unsupported_languages`, `download_required`, `activation_required`, `download_failed` and `not_allowed`. It reports no usage, so the router charges the reservation; `maxTokens` and temperature have no effect. The browser-managed identity cannot be pinned and output varies. Verification uses a fake `LanguageModel` only on Node and Chromium, preserving any real global without calling it. Real-device verification, stable/beta smoke tests and session-creation cost remain M2 exit work; the router probes readiness before selection, without retrying a dispatched call on another provider. The router now supports host availability and download hooks, cached-before-download ordering for ADR-ordered routes, shared download decisions, optional site-storage `persist()`, per-call feature requirements and class-change notices through `snapshot.routes[role].changedFrom`. Routed `withStructuredOutput` forwards constrained decoding and validates replies with fixed errors. `RuntimeOptions.outputSafety` adds a host hook for routed reply text and tool-call arguments, checked before non-streaming return and before each growing streamed chunk, with one final check. Blocks fail `denied`; hook failures fail closed with `unavailable`, fixed errors and content-free diagnostics and span outcomes. Without a hook, core reports `output_safety_unset` once per routed instance. The host owns the hook's handling of reply text; earlier allowed chunks cannot be retracted, and direct models, tool outputs, capability results and other display callbacks remain outside this check. Mock-provider tests cover the LangGraph `messages` stream on Node and Chromium. `checkWebLLMModel` reports cached weights, not a loaded engine; WebLLM must still load before prepare until lazy host construction ships. The Prompt API reports no byte size, a known gap against ADR-0006 decision 5; hosts must state that the browser manages the download and its size is not reported. Remote providers, download-consent UI and per-call provider caps from the router remain unimplemented. The M2 exit record (`docs/m2-exit-record.md`) records one real lesson each on Built-in AI and on WebLLM over WebGPU on the maintainer's Apple M5 Pro with Chrome 155, as demonstrations: AT-03 holds on that device, and AT-04 holds for page requests after caching, while dedicated-worker requests, first download, p50/p95 and long tasks remain unmeasured. Spikes run only when a milestone needs their answer (brief §16.2). Spike code is throwaway: keep it out of `packages/` and never promote it to package code.

`@galaxie/storage-indexeddb` now provides a scoped, versioned LangGraph checkpoint saver with transaction-completion barriers and Chromium parity/reopen tests; core now exposes session adoption and `restore()` for pending interactions, and host-local restores them after reload through the existing React surface. Restored runs receive fresh IDs and budgets and all data labels. Durable inbox reconciliation, retention, fencing and logout remain later M3 slices.

`packages/react` now provides a typed registry, `useAgentSnapshot`, `AgentSurface` and headless `education.Quiz/v1`, `education.WritingPrompt/v1`, `education.Feedback/v1` and `education.Progress/v1` entries. Hosts pass `ui: registry.bindings({ surfaces })` when creating the instance so core checks required components and surfaces, rejects unbound pending interactions, and validates dispatched actions and payloads. The surface validates props and declared URLs, uses render-time identity and duplicate guards, and owns no instance lifecycle. Labels come from trusted entries and model text renders as React text only. Origin allowlists do not constrain paths or queries; trusted URL extractors must list every single-attribute URL. Drafts remain component-local and reset on remount; draft persistence stays outside this M3 slice. Chromium tests cover schemas, rendering, Strict Mode subscriptions, stale actions and a real LangGraph resume. React source and build imports are enforced by `check:deps`.

`examples/english-tutor` (`@galaxie/example-english-tutor`) now runs lesson loading, one committed quiz, deterministic grading, private sentence review, Feedback, progress saving and Progress with mock providers on Node and headless Chromium. Accepted UI payloads gain all bound-schema labels and register private strings before resume; unreadable schemas conservatively add `private-user` for non-empty text. The default policy keeps the learner sentence in-browser. Grading is local practice only. A parent graph projects run output to `{ lessonId, score, total, saved }`; Quiz props omit the answer key, and Feedback reveals correct option labels after grading. Raw `stream` events include graph state and the answer key: hosts must never render them as display data. The projection covers run output and interaction props only. The checkpointer holds the sentence and answer key and must stay on-device, scoped to the learner and session; the default in-memory saver does. The `progress.save@1` binding must derive the learner from trusted host context and authorize lesson access before writing; arguments contain only `{ lessonId, score, total }`. `examples/host-local` now wires the tutor in Vite with a strict CSP and Trusted Types, local bindings and a demonstration output safety hook; its headless Chromium loop records same-origin GETs with no learner sentence using mocks, and checks default-mode load and inert worker construction without real models. Reload restores the pending quiz or writing prompt from IndexedDB with an app/principal session key and a host Web Lock; drafts reset on reload. Inbox reconciliation and core fencing remain later M3 slices, and real providers/devices remain exit work. Optional model-generated quiz explanations and rubric quality evaluation are outside this slice.

Routing, labels, consent and model budgets apply only through `host.langchain.chatModel(role)`; trusted agent code holding its own model can bypass them (ADR-0002). The router's `maxTokens` is a reservation, so a call can use more and an actual-usage overrun fails the run only after that call returns. WebLLM separately sends its provider-level `maxTokens` as the per-request output limit `max_tokens` (default 1024); the router does not pass its reservation as that limit. `getCredential` hands credentials to page code per call, where XSS or a malicious same-origin dependency can read them. Hosts should supply short-lived, host-proxy-scoped tokens rather than long-lived provider keys (ADR-0012).

## Read first

1. `docs/galaxie-project-brief.md`: the source of truth for scope, architecture, security and the roadmap. Start with §0.
2. `docs/adr/`: one file per decision. Follow Accepted ADRs. Proposed ADRs are working defaults that a spike or milestone must confirm.
3. `docs/system-design.md`: components, package boundaries, contracts and runtime flows. Read it before you add a package or change a contract.
4. `docs/framework-overview.md`: role, audiences and the roadmap at a glance.

Handoff prompts: brief §21 (implementation) and §22 (review).

## Commands

Node.js 24 and pnpm 11 (through Corepack).

- `pnpm install`
- `pnpm check`: everything CI runs. Run it before you report work as done.
- `pnpm format`: apply Biome formatting and safe fixes.

The compiler settings are strict (system design §10): relative imports end in `.js`, type-only imports use `import type`, exported functions declare their return types, and syntax that TypeScript cannot erase, such as `enum`, is not allowed.

## Rules

- Everything committed is in English: code, comments, docs, commit messages, issues and pull requests.
- New source files start with the SPDX header from ADR-0015:
  ```ts
  // SPDX-FileCopyrightText: 2026 Nguyễn Xuân Vĩnh
  // SPDX-License-Identifier: AGPL-3.0-only
  ```
- Do not merge, copy or adapt code from outside contributors. There is no contributor license agreement yet (ADR-0015).
- Never commit secrets: API keys, tokens, credentials or `.env` files. A local gitleaks pre-commit hook blocks them.
- The security baseline (ADR-0012) is mandatory. Never weaken a guarantee to make a test pass.
- Never describe galaxie as secure, compliant, certified or suitable for regulated or high-risk uses, in docs, comments, commit messages or anything user-facing. Describe the controls and their documented limits instead (README, "Intended use and disclaimer").

## Maintainer-only notes

`internal/` is git-ignored here. On the maintainer's machine it is a separate private git repository with its own history. It holds planning, business and legal notes, and raw review outputs.

- Read it when it is present and relevant to the task.
- Git commands run inside `internal/` act on that repository, not on this one.
- Never copy its content into tracked files, commit messages, pull requests or issues.
- Never remove `/internal/` from `.gitignore` or force-add files from it.

Two local tools are git-ignored the same way. They exist only where the maintainer set them up:

- `.codegraph/`: the CodeGraph index of this repository. When it is present, use it to locate and read code. Run `codegraph sync` if it looks stale.
- `.beads/`: the Beads (`bd`) backlog, kept out of this repository (stealth mode). Use it for work that spans sessions. It is tracker content, so write it in English.
  - Never copy it into tracked files, and never let `bd` use this repository's remote as its Dolt remote.
  - Never change its Dolt remote, or run `bd dolt push` or `bd sync`, without the maintainer's approval.
