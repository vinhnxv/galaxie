## Project status

MVP evidence is recorded in the [exit record](docs/mvp-exit-record.md), with AT-01 through AT-36 mapped to existing tests and records, partial evidence and unmeasured items stated explicitly, and the maintainer's Go/Revise decision pending. A Node consistency test checks AT coverage, order, statuses and cited evidence; this slice changes no runtime or example behavior.

galaxie has its first four M1 runtime slices: `packages/core` provides lifecycle, identity, cancellation, replayable in-memory events, allowlisted OpenTelemetry spans, a capability broker with grants and validation, sticky data labels and argument shapes, and finite budgets for steps, tool calls, wall clock, payloads, tokens and cost. Its model router enforces ordered per-role providers, destination classes, labels, shared consent and per-call credentials, and publishes selected routes in snapshots. `packages/core` also owns run segments and an accepted/consumed submission inbox with checkpoint-confirmed, deduplicated dispatch and optional durable recovery. Its M1 exit controls check interaction URL origins before pending state and gate opt-in development trace text by live run labels and the declared trace destination. `packages/adapter-langgraph` routes native chat calls, reads pending interactions from checkpoints and resumes them by interrupt ID; `requestInteraction(request, config)` works after an await on Node and Chromium. Its twelve parity cases cover interrupts, subgraph re-execution and durability modes; additional Node/Chromium tests cover interaction policy, lifecycle, budgets and complete span trees. The explicit-config API list is in `tests/conformance/README.md`, beside the compatibility matrix, and system design §9 maps M1 guarantees to code and tests. The adapter installs a synchronous context shim only when no global context exists; Node hosts needing async LangChain context must initialize real `AsyncLocalStorage` before the first prepare (system design §6). Parallel interrupts, static breakpoints, ID-less interrupts and multiple requests per node remain unsupported; `packages/models` ships the deterministic mock and `@galaxie/models/webllm`, a lazy WebLLM 0.2.86 worker provider with a shared FIFO queue, reset per request, cancellation, final-only usage, `jsonSchema`, provider-level `withStructuredOutput`, a commit-pinned record with SRI, content-free progress and typed errors, and a page-side device report. Loading, streaming, cancellation and schema wiring have fake-engine coverage only on Node and Chromium; real-device verification, prefill abort latency and the cost of foregoing KV-cache reuse remain unmeasured. After worker failure or device loss the selected provider keeps failing `unavailable`, without fallback; recovery requires a new handle, model and runtime. Hosts bundle and start one worker per runtime and may declare `structured-output` for routing. SRI covers config, library and tokenizer, not weight shards; validation requires an immutable weight revision. Only the worker needs the download hosts and WASM CSP directives (system design §8.4). `@galaxie/models/builtin-ai` adds a page-only Chrome Prompt API model with one session per call, streaming, cancellation and provider-level schema output through `responseConstraint` with the schema omitted from input. Configure input/output languages and register it with destination `in-browser`, zero pricing, features `['streaming', 'cancellation', 'structured-output']` and the role's languages. Calls require `available` and never download; hosts use `checkBuiltInAI` to probe and `prepareBuiltInAI` from an intentional download click, with content-free progress. Typed reasons distinguish `no_api`, `unsupported_languages`, `download_required`, `activation_required`, `download_failed` and `not_allowed`. It reports no usage, so the router charges the reservation; `maxTokens` and temperature have no effect. The browser-managed identity cannot be pinned and output varies. Verification uses a fake `LanguageModel` only on Node and Chromium, preserving any real global without calling it. Real-device verification, stable/beta smoke tests and session-creation cost remain M2 exit work; the router probes readiness before selection, without retrying a dispatched call on another provider. The router now supports host availability and download hooks, cached-before-download ordering for ADR-ordered routes, shared download decisions, optional site-storage `persist()`, per-call feature requirements and class-change notices through `snapshot.routes[role].changedFrom`. Routed `withStructuredOutput` forwards constrained decoding and validates replies with fixed errors. `RuntimeOptions.outputSafety` adds a host hook for routed reply text and tool-call arguments, checked before non-streaming return and before each growing streamed chunk, with one final check. Blocks fail `denied`; hook failures fail closed with `unavailable`, fixed errors and content-free diagnostics and span outcomes. Without a hook, core reports `output_safety_unset` once per routed instance. The host owns the hook's handling of reply text; earlier allowed chunks cannot be retracted, and direct models, tool outputs, capability results and other display callbacks remain outside this check. Mock-provider tests cover the LangGraph `messages` stream on Node and Chromium. `checkWebLLMModel` reports cached weights, not a loaded engine; WebLLM must still load before prepare until lazy host construction ships. The Prompt API reports no byte size, a known gap against ADR-0006 decision 5; hosts must state that the browser manages the download and its size is not reported. `@galaxie/models/openai` now supplies a call-scoped OpenAI-compatible provider for host proxies and user endpoints, with per-call credentials, fixed errors, usage, streaming, cancellation and schema output tested through injected fetch on Node and Chromium. Download-consent UI and per-call provider caps from the router remain unimplemented. The M2 exit record (`docs/m2-exit-record.md`) records one real lesson each on Built-in AI and on WebLLM over WebGPU on the maintainer's Apple M5 Pro with Chrome 155, as demonstrations: AT-03 holds on that device, and AT-04 holds for page requests after caching, while dedicated-worker requests, first download, p50/p95 and long tasks remain unmeasured. Spikes run only when a milestone needs their answer (brief §16.2). Spike code is throwaway: keep it out of `packages/` and never promote it to package code.

`@galaxie/storage-indexeddb` now provides a scoped, versioned LangGraph checkpoint saver and `saver.recovery` on the same connection. Core's optional `RecoveryStore` durably accepts submissions, reconciles them before restore publication and journals write capabilities with deterministic effect IDs and input digests. Successful receipts replay without invocation; unknown `retry: 'none'` writes fail `outcome_unknown` without repeating. Host-local supplies both ports. Restored runs receive fresh IDs/budgets and all data labels; accepted payloads and replayed outputs re-register private strings. Keep recovery data on-device under the checkpointer's app/principal scope, with one active owner/instance per session. There is no unknown-outcome reconciliation API yet; reconcile with the backend by effect ID before a new session could repeat the operation. Crashes after an intermediate checkpoint with no pending interrupt cannot finish the run or replay later writes. Node/Chromium fault tests cover all durability modes, with IndexedDB reopen in Chromium. Storage lifecycle now adds host-controlled retention (7-day history, 30-day inactivity), explicit session deletion, version-change handover, fixed-code error observation and unrecoverable markers. Core records agent identity before start and refuses missing or incompatible metadata before restore. Host-local shows quota/reload/recovery outcomes; its explicit sweep, Start over or Sign out removes session data. Persistence is not permanence: browser eviction returns to a fresh start. The M3 exit record (`docs/m3-exit-record.md`) records a real-model run of host-local on the maintainer's Apple M5 Pro with Chrome 155: reload restore, double submits, a two-tab handover and sign-out from a non-owner tab. It maps AT-08, AT-09, AT-31, AT-18, AT-13 and AT-34 to their automated tests; renderer crashes and real bfcache restores remain unmeasured, and the external developer trial is still open. Core app-wide Web Lock ownership now supports cooperative handover, timed forced takeover and bfcache verification. Every IndexedDB state write checks the shared app epoch inside its transaction; cross-principal takeovers fence earlier savers. Host-local offers "Use here" and disables a former owner until reload. Per-principal logout generations now fence every state write, and one transaction wipes principal data. Core broadcasts invalidation across tabs; host-local offers Sign out even before model preparation or after ownership loss. See the [logout contract](docs/system-design.md#86-logout) for delivery and host-cleanup limits.

`packages/react` now provides a typed registry, `useAgentSnapshot`, `AgentSurface` and headless `education.Quiz/v1`, `education.WritingPrompt/v1`, `education.Feedback/v1` and `education.Progress/v1` entries. Hosts pass `ui: registry.bindings({ surfaces })` when creating the instance so core checks required components and surfaces, rejects unbound pending interactions, and validates dispatched actions and payloads. The surface validates props and declared URLs, uses render-time identity and duplicate guards, and owns no instance lifecycle. Labels come from trusted entries and model text renders as React text only. Origin allowlists do not constrain paths or queries; trusted URL extractors must list every single-attribute URL. Drafts remain component-local and reset on remount; draft persistence stays outside this M3 slice. Chromium tests cover schemas, rendering, Strict Mode subscriptions, stale actions and a real LangGraph resume. React source and build imports are enforced by `check:deps`.

`examples/english-tutor` (`@galaxie/example-english-tutor`) now runs lesson loading, one committed quiz, deterministic grading, private sentence review, Feedback, progress saving and Progress with mock providers on Node and headless Chromium. Accepted UI payloads gain all bound-schema labels and register private strings before resume; unreadable schemas conservatively add `private-user` for non-empty text. The default policy keeps the learner sentence in-browser. Grading is local practice only. A parent graph projects run output to `{ lessonId, score, total, saved }`; Quiz props omit the answer key, and Feedback reveals correct option labels after grading. Raw `stream` events include graph state and the answer key: hosts must never render them as display data. The projection covers run output and interaction props only. The checkpointer holds the sentence and answer key and must stay on-device, scoped to the learner and session; the default in-memory saver does. The `progress.save@1` binding must derive the learner from trusted host context and authorize lesson access before writing; arguments contain only `{ lessonId, score, total }`. `examples/host-local` now wires the tutor in Vite with a strict CSP and Trusted Types, local bindings and a demonstration output safety hook; its headless Chromium loop records same-origin GETs with no learner sentence using mocks, and checks default-mode load and inert worker construction without real models. Reload restores the pending quiz or writing prompt from IndexedDB with an app/principal session key and the core app-wide Web Lock; drafts reset on reload. Accepted answers now reconcile through `saver.recovery`; core ownership and app-wide storage fencing now cover cooperative and forced takeover, and real providers/devices remain exit work. Optional model-generated quiz explanations and rubric quality evaluation are outside this slice.

`examples/host-remote` now runs the unchanged tutor with a same-origin OpenAI-compatible quiz stub, HTTP lesson/progress bindings, renewable 300-second demo tokens and host-rendered save confirmation. Feedback stays in-browser (mock-only in test mode; available Chrome Built-in AI in default mode). It uses MemorySaver, so reload starts over. Node and headless Chromium tests cover the full loop, both decline paths, token renewal and expiry, Host/Origin checks, CSP and sentence-free loopback requests. The backend is a demonstration with one learner and no upstream provider; real-provider verification and the second external developer trial remain outside this slice.

Ownership protects local writes only when hosts compose `acquireOwnership({ appId, fence: saver.fencing, onHandoverRequest })` with runtime disposal. The lock is `galaxie:<appId>:runtime`; "Use here" requests cooperative handover before a timed forced takeover. A former host owner shows "The lesson moved to another tab." and disables input until reload. Epoch checks share each write's transaction and span every principal of the app. Reads remain available. Fencing does not protect against a tab that bypasses ownership; an already-sent remote request may complete, and a synchronous loop delays noticing loss. Backends can reject stale epochs when the host implements that protocol; galaxie sends no epoch headers. Node hosts need both Web Locks and `BroadcastChannel`. See [the ownership contract](docs/system-design.md#85-tab-ownership-and-takeover).

Routing, labels, consent and model budgets apply only through `host.langchain.chatModel(role)`; trusted agent code holding its own model can bypass them (ADR-0002). The router's `maxTokens` is a reservation, so a call can use more and an actual-usage overrun fails the run only after that call returns. WebLLM separately sends its provider-level `maxTokens` as the per-request output limit `max_tokens` (default 1024); the router does not pass its reservation as that limit. `getCredential` hands credentials to page code per call, where XSS or a malicious same-origin dependency can read them. Hosts should supply short-lived, host-proxy-scoped tokens rather than long-lived provider keys (ADR-0012).

`@galaxie/tools-mcp` now binds allowlisted, pinned MCP tools through principal-scoped Streamable HTTP sessions on protocol 2025-11-25, with byte/idle limits and a loopback reference server tested through the broker on Node and Chromium. Write tools run through host-rendered, single-use confirmations when the host configures `CreateOptions.confirmations`; without that option they still fail `unsupported`. Core publishes frozen arguments in host-only confirmation snapshots, and `@galaxie/react` supplies a separate host registry and `ConfirmationPrompt`. Approvals expire and are invalidated by policy changes, run end, disposal and configured logout/takeover signals; they are never persisted. See [confirmation wiring and limits](packages/react/README.md). Pinning detects metadata changes only.

Core now exports pure `createManifest` generation with Standard JSON Schema conversion, preserved `x-galaxie` annotations and fixed errors for invalid definitions or unrepresentable schemas. The root build writes and verifies the tutor's manifest and schemas under `dist/galaxie`, with SHA-256 digests for the entry, shipped-file inventory and nearest lockfile. Verification writes nothing and rejects missing, added or changed artifacts. Custom refinements remain runtime-only. Digests prove only a match against the checked manifest: hosts must obtain the manifest, or pin its digest, from trusted build output or a reviewed commit. Without signing, replacing both package and manifest passes verification; hashes do not prove safe behavior. See [manifest layout and trust model](docs/system-design.md#62-generated-agent-manifests).

`@galaxie/eslint-plugin` now provides five ESLint 10 flat-config rules for agent packages: direct network, storage, DOM and HTML sinks, eval-style execution, and direct model-provider access. ESTree scope analysis respects shadowed locals without type information or runtime dependencies. RuleTester covers the rules, and a Node conformance test lints all unchanged tutor sources after type stripping. ## Commands

Node.js 24 and pnpm 11 (through Corepack).

- `pnpm install`
- `pnpm check`: everything CI runs. Run it before you report work as done.
- `pnpm format`: apply Biome formatting and safe fixes.

The compiler settings are strict (system design §10): relative imports end in `.js`, type-only imports use `import type`, exported functions declare their return types, and syntax that TypeScript cannot erase, such as `enum`, is not allowed.

## Rules

- Everything committed is in English: code, comments, docs, commit messages, issues and pull requests.
- New source files start with the SPDX header from ADR-0015:
  ```ts
  // SPDX-FileCopyrightText: 2026 Nguyễn Xuân Vĩnh
  // SPDX-License-Identifier: AGPL-3.0-only
  ```
- Do not merge, copy or adapt code from outside contributors. There is no contributor license agreement yet (ADR-0015).
- Never commit secrets: API keys, tokens, credentials or `.env` files. A local gitleaks pre-commit hook blocks them.
- The security baseline (ADR-0012) is mandatory. Never weaken a guarantee to make a test pass.
- Never describe galaxie as secure, compliant, certified or suitable for regulated or high-risk uses, in docs, comments, commit messages or anything user-facing. Describe the controls and their documented limits instead (README, "Intended use and disclaimer").

## Maintainer-only notes

`internal/` is git-ignored here. On the maintainer's machine it is a separate private git repository with its own history. It holds planning, business and legal notes, and raw review outputs.

- Read it when it is present and relevant to the task.
- Git commands run inside `internal/` act on that repository, not on this one.
- Never copy its content into tracked files, commit messages, pull requests or issues.
- Never remove `/internal/` from `.gitignore` or force-add files from it.

Two local tools are git-ignored the same way. They exist only where the maintainer set them up:

- `.codegraph/`: the CodeGraph index of this repository. When it is present, use it to locate and read code. Run `codegraph sync` if it looks stale.
- `.beads/`: the Beads (`bd`) backlog, kept out of this repository (stealth mode). Use it for work that spans sessions. It is tracker content, so write it in English.
  - Never copy it into tracked files, and never let `bd` use this repository's remote as its Dolt remote.
  - Never change its Dolt remote, or run `bd dolt push` or `bd sync`, without the maintainer's approval.
