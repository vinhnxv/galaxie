## Execution and LangGraph

- LangGraph.js routed `bindTools` and `host.langchain.capabilityTool` have mock-only scenarios on Node and Chromium, and no real-model result is claimed. The helper refuses to offer a write without `approval: 'confirm'` and host confirmation coverage. The ADK JavaScript helper and the Python `capability_tool` helpers (ADK, DSPy, pydantic-ai) apply the same rule: they refuse a capability that is not a read unless it is bound with `approval: 'confirm'` and the runtime has host confirmation coverage, and they refuse an unbound name, with the fixed `invalid` error. The ADK helpers return that error to the model as fixed text; the DSPy and pydantic-ai helpers end the run with it. The core broker's treatment of ordinary capability calls is unchanged, so a direct `capabilities.call` from agent code is not affected. The evidence is mock and in-process scenarios only. A declined confirmation returns fixed `denied` text and the model may request the write again, bounded by the tool-call budget. Output safety checks tool-call arguments and reply text, not tool-call names or IDs. A provider whose `bindTools` returns a wrapped runnable does not receive the routed destination marker. Custom author-built tools, including wrappers that replace a helper's declarations, are outside this guarantee: authors must preserve broker calls, labels, budgets, effect scopes and host confirmations. A native `ToolNode` must use `{ handleToolErrors: false }` so fatal broker failures end the run; the helper itself converts only `denied` and `invalid` into fixed model-visible messages. The full node config and deterministic per-task call order remain necessary for recovery ([tool helper](../packages/adapter-langgraph/README.md#model-chosen-capability-tools), [mock scenarios](../tests/conformance/langgraph-tools.test.ts)).
- Parallel interrupts and multiple interaction requests in one node remain unsupported in shipped code ([adapter limits](../packages/adapter-langgraph/AGENTS.md#limits)). The [Node spike](../spikes/parallel-interrupts/README.md) records parallel interrupts as **refused**: an answered no-state-write sibling retains a stale interrupt without a completion marker. Ask the questions before the fan-out, or chain interrupting branches so at most one task pauses per superstep, with one request per node. Several top-level requests in one node are **supported as a proven design, implementation pending review**; until that lands, split requests into separate nodes. Repeated child pauses and multi-pause/later-ordinal materialized surfaces remain refused. [Proposed ADR-0030](adr/0030-several-engine-pauses-published-one-at-a-time.md) records the obligations and limits; the [interrupt-sequence case](../tests/conformance/cases/interrupt-sequence.ts) proves the current author workaround.
- The [static-breakpoint/ID-less-interrupt spike](../spikes/static-breakpoints/README.md) records static breakpoints as **alternative**. Compiled `interruptBefore` and `interruptAfter` are refused at prepare, including `graph.config` and discoverable subgraphs, even for unreachable nodes. An invisible override ends the run `unsupported` at its first pause after preceding nodes ran. Use an explicit `requestInteraction` gate with continue/reject edges; the [replacement cases](../tests/conformance/README.md#static-breakpoint-refusal-and-gate-replacement) prove both actions and reload with memory and Chromium IndexedDB. Continue never replaces a host write confirmation. A synthesized static reject leaves its checkpoint paused and inbox accepted, so restore replays it; without the inbox the pause is republished. A single ID-less `requestInteraction` on a root checkpoint task now supports task-derived identity, bare resume and recovery on Node and Chromium, including a body-invoked child without a child checkpoint namespace. Compiled child namespaces, parallel/mixed pauses, unfinished siblings, repeated calls in one node, malformed requests/IDs and ID-less surfaces fail `unsupported`. Exact valid `NodeInterrupt`/raw `GraphInterrupt` requests publish once and fail on the first answer; with recovery, the accepted entry remains and restore retries the failure. The [pause-time discriminator spike](../spikes/langgraph-nodeinterrupt-pause-time/README.md) records **alternative**: P7/P8 break strict parsing or stream parity, P9/P10 lose restore signals, and P12 verifies the complete-config `requestInteraction` replacement; shipped behavior is unchanged. A refused second call leaves the entry accepted and restore fails `executor_error`. Always pass complete node config. See [the shipped limits and registration scope](../packages/adapter-langgraph/README.md#id-less-interrupts) and [conformance evidence](../tests/conformance/README.md#id-less-interrupts). Second pauses inside body-invoked children, repeated child pauses, loop revisits and real models remain unmeasured. Static breakpoints remain unsupported; explicit gates are the alternative.
- Without a recovery store, a parent node's broker-bound write before an interrupting child repeats on resume. With recovery and the node config explicitly forwarded, the stable task scope replays the successful receipt: two parent bodies, one host write, including after IndexedDB reopen and restore. Call order within a task must be deterministic. Effects outside the broker still repeat; put side effects after interrupts or in a separate completed node ([parent-effect tests](../tests/conformance/subgraph-effects.test.ts), [scope and restore tests](../tests/conformance/subgraph-effect-scopes.test.ts), [AT-35](mvp-exit-record.md#acceptance-tests)).
- Implicit async LangChain context is unavailable under the synchronous shim; pass node config explicitly, and initialize real `AsyncLocalStorage` before the first prepare on Node when async ambient context is required ([context inventory and matrix](../tests/conformance/README.md#explicit-config-and-context)).
- LangGraph facades without native `transform()` or checkpoint `getState()` are unsupported ([adapter contract](system-design.md#6-core-runtime-and-contracts)).
- Universal Python execution, adapters beyond the implemented LangGraph.js and experimental LangGraph Python/pydantic-ai/DSPy paths, distributed agents, cross-device resume and always-on scheduling are outside the MVP ([scope](galaxie-project-brief.md#52-outside-the-mvp), [Python adapter](../packages/adapter-pyodide/README.md)).
- The JavaScript executor runs on the main thread; the experimental Python executor runs in a dedicated Pyodide Worker under the scoped exception in ADR-0018. Real-inference long tasks remain unmeasured ([execution context](adr/0003-executor-execution-context.md), [Python decision](adr/0018-python-agents-through-pyodide.md), [M2 measurements](m2-exit-record.md#not-measured)).

Reload restore requires the scoped IndexedDB byte-record port and recovery store; without that port, cancellation or Worker loss still discards in-memory state. LangGraph Python streaming and subgraphs are available, including child interrupts and durable restore. Its driver accepts asynchronous text model calls and checked streaming; native tool-call parts and multimodal replies remain refused. The November 2026 spike records text-protocol alternatives for binding/replies, streaming, confirmed writes, the safety floor and durable replay. The [execution-identity rerun](adr/0018-python-agents-through-pyodide.md#execution-identity-rerun-2026-11-13) records **refused**: its test-local driver scope retains swallowed terminal codes, but read effect IDs change on replay and abrupt Worker loss before a tool checkpoint has no public core retry path. An already parked confirmation can still invoke a sibling write after the latch; no production helper ships. Neighbouring binding/message shapes remain refused. The [November 14 measurements](adr/0018-python-agents-through-pyodide.md#langgraph-python-tool-call-measurements-2026-11-14) normalize `bind_tools` and default structured-output refusal to fixed `unsupported`, still catchable as `NotImplementedError`, including Worker construction and run. Ordinary author tools may use `capabilities.call(..., tool=True)` over the checked text protocol; default ToolNode handling propagates failures, while explicit handlers may swallow host failures. Pydantic validation can return native error text before the broker; broker `invalid` also covers binding failures and cannot be classified as schema-only text. Both text-protocol replay modes pass real page reloads on local Chromium, Firefox and WebKit. Split streamed IDs/names expose native merge differences; no helper or streamed tool-call admission follows. The replacement uses an author-validated JSON text request and a direct broker call, with no ToolNode, schema-constrained choice or streamed tool deltas, and without the helper tool-policy flag. Keep terminal failures uncaught and configure host-confirmed writes explicitly; see the [author recipe](../packages/adapter-pyodide/README.md#langgraph-python-model-chosen-calls-through-text). Streamed calls require a provider declaring streaming, including implicit graph message streaming. Graph chunks must have bounded JSON projections; raw graph streams remain untrusted working state and are delivered live without replay. A checkpoint tuple or list must fit one 1 MiB bridge message after base64. RAG offers opt-in persistent passage review on both LangGraph executors, with mock Node/Chromium parity and reload coverage; the default flow stays in memory. A `pydantic-ai-python` executor runs pydantic-ai agents with tool calls, checked streaming and deferred-tool approval interactions; its conversation snapshots restore pending approvals after a fresh Worker and reopened scoped IndexedDB with the matching recovery store. Without the byte-record port, cancellation or Worker loss still discards pending state. Tool-less `NativeOutput` uses routed `jsonSchema` constraints, requires `structured-output`, and charges validation retries to the host route and shared run repair limits. Native output with tools, deferred requests or a string schema template is refused at prepare, as are callable agent settings and every agent setting except `stop_sequences`; later-contributed tools or settings are refused before the bridge. Provider-specific settings stay refused because provider selection, request shaping and output limits belong to the host. Multimodal content, builtin/native tools and arbitrary mid-run continuation remain unsupported. Use `galaxie.pydantic_ai.run_child(ctx, child, prompt, key='')` for delegation: it shares usage and limits, derives child identity from message position and key, and separates native repair counters. Plain nested model runs, child streams and nested `Executor.run` fail `unsupported` before bridge requests; missing request `run_id` also fails closed, including when a history processor causes upstream merging to discard it. The helper refuses a child whose selected model, including a `model=` override, is not a `GalaxieModel`, but plain non-bridge models and direct trusted `capabilities.call` remain outside the guard. This guard is accident-proofing; ADR-0012 controls remain in JavaScript. Scripted changed-ID recovery preserves the helper's scope and effect ID and writes once, while the ID-sensitive control writes twice; real-provider ID regeneration remains unmeasured. Replay must preserve call order and structure. Opt-in `run_child(..., hoist_approvals=True)` supports one hoisted child per pause with exactly one pending approval, no external calls and at most 128 KiB of child state. The executor validates its reserved metadata at publish, restore and re-entry and requires the child call ID, name and arguments together in interaction props. Several hoisted children, several child approvals, external child calls, nested hoists and oversize state are refused. A tool body may use only one hoisting child; a second fails before its own work, though an earlier approved child may already have written. Other author metadata remains unvalidated and snapshots are not authenticated. No helper child streaming or child stream paths ship, so `subgraphs` stays false (probe S1). Python wire tests, a driver tripwire and Node stream assertions pin parent-only output with empty paths. The six delegation and child-approval cases match their existing goldens in headless Chromium, including real page reloads with reopened scoped IndexedDB. Firefox, WebKit, general nested checkpoints and Node crash-after-write replay of a hoisted resume are unmeasured. See the [child approval evidence](../tests/conformance/README.md#pydantic-ai-child-approval-hoist) and [delegation evidence](../tests/conformance/README.md#pydantic-ai-agent-delegation-probes). Native-output evidence is scripted CPython, Node Pyodide and Chromium parity only; real-model constraint enforcement is unverified. The RAG example now offers it for mock tool-calling models, with deferred passage review, reload and Start over; its hands-on Chrome check remains unverified. The bundled WebLLM and Built-in AI providers do not declare tool calling, so default mode omits this choice. The tutor port remains unimplemented ([adapter limits](../packages/adapter-pyodide/README.md)).

- A confirmation fails `unsupported` when it sits beside other calls in one model turn. ## Storage and recovery

- An optional binding hook, `reconcile(effectId, context)`, can resolve a restored `dispatched` or `outcome_unknown` write with `retry: 'none'` ([ADR-0029](adr/0029-reconcile-hook-for-unknown-outcome-writes.md)). Core consults it once per restored call, before approval, with the abort signal but no call input. `applied` with an output settles `succeeded` through the usual schema validation, payload bound and labels, without invoking or approval. `not-applied` replays under the same effect ID with fresh approval where required. `unknown`, throws, rejections and malformed answers fail `outcome_unknown`. A consult exceeding `timeoutMs` fails `timeout` in either approval mode; cancellation or disposal fails `cancelled`. These failures leave the receipt `outcome_unknown`. Without a hook, behavior is unchanged: the write stays blocked and the host reconciles outside the framework before starting a potentially repeating operation.

  The host's `not-applied` answer must mean no request sent before the answer can still apply that effect ID, while the replay that core sends next is admitted (for example by refusing earlier owner generations). An absence check cannot exclude a late request from a former owner ([ADR-0009](adr/0009-multi-tab-ownership.md)). Core cannot verify the answer; a false `not-applied` can repeat a write.

  Measured: [core unit tests](../packages/core/test/reconcile.test.ts) cover binding validation, applied schema/payload/label checks and private values, replay and timeout in both approval modes, fail-closed answers, cancellation, disposal, one consult per restored call and unchanged behavior without a hook. [Conformance](../tests/conformance/reconcile.test.ts) uses LangGraph and an in-test mock backend on Node with memory storage and Chromium with IndexedDB reopened between runtimes. The broker is executor-neutral by construction, but the hook is unmeasured through ADK JavaScript, ADK Python, ADK Go, Pyodide and DSPy; DSPy keeps its own Python-side replay journal. Firefox, WebKit, real backends (including real HTTP backends) and host answer soundness are unmeasured.
- For an `httpCapability` declared `retry: 'idempotency-key'`, the effect ID is sent as the `Idempotency-Key` header, so a backend that deduplicates on it makes a repeat safe; galaxie does not guarantee the backend does, and the evidence is injected-fetch and loopback only ([effect recovery](system-design.md#83-a-capability-call)).
- Recovery data is not migrated across builds. Session, submission and effect records carry `formatVersion` (current value `1`); records without it, including the 0.1.0 shape, read as version 1. A newer version fails closed with a clear error (`newer_record` from IndexedDB, mapped to `unrecoverable` on restore). The stamp cannot distinguish unstamped receipts keyed by run segment from task-scoped ones. Write receipts recorded before task-scoped effect IDs are keyed by run segment, and a newer build cannot find them, so resuming such a session on a newer build can repeat a write, including a `retry: 'none'` write. No migration exists. Hosts must resume with the build that created it, or Start over and reconcile with the backend by effect ID before upgrading. A 0.1.0 build reads stamped records as corrupt because it enforces strict key counts, so hosts must not roll back across this change while sessions are pending. A host that talks to the IndexedDB saver directly must not offer "Start over" for a `newer_record` failure; retain the data and resume with a build that supports its format. `restore()` reports a newer IndexedDB record as the same generic `unrecoverable` error as a corrupt one, so a host that only sees the restore error cannot tell them apart yet, and the host-local example offers Start over for both ([recovery contract](system-design.md#82-reload-and-crash-recovery)).
- Reload recovery cannot finish an arbitrary intermediate checkpoint with no pending interrupt or replay later writes from that point ([recovery limits](system-design.md#82-reload-and-crash-recovery)).
- The checkpoint saver's `exportSession` supplies content-free metadata by default and personal checkpoint content only with exact `personalContent: true`, which hosts must bind to an explicit user action. Host-local wires a metadata-summary download and a host-confirmed personal-content download; host-remote has no export UI. Export is lossy and supplies no import, sync, cross-device recovery or durable runtime-event history ([export semantics](../packages/storage-indexeddb/README.md#explicit-session-export), [scope](galaxie-project-brief.md#52-outside-the-mvp)).
- IndexedDB storage is not encrypted by the package and browser persistence is not permanence, so eviction can return a fresh start ([storage limits](../packages/storage-indexeddb/AGENTS.md#limits)).
- Ownership and logout need host composition, cannot fence a tab that bypasses ownership, and cannot undo an already-sent remote effect ([ownership](system-design.md#85-tab-ownership-and-takeover), [logout](system-design.md#86-logout)).

## Security boundaries

- Trusted-first execution supplies no sandbox for arbitrary JavaScript, unreviewed agents or same-origin dependencies, which can bypass SDK-controlled paths ([trust boundary](security-review.md)).
- Data labels do not detect paraphrases sent to allowed destinations. Core rejects interaction URL candidates containing registered private strings in raw or twice percent-decoded form, with `+` treated as a space, unless `private-user` policy allows `third-party`. Parser-normalized candidates receive the same checks, including tab/newline/carriage-return stripping. When whole-URL decoding fails, each maximal run of valid percent escapes is decoded independently; invalid UTF-8 runs stay raw. The broker applies the same raw and twice-decoded matching to every argument string and key, including structured fields, only when private-user policy disallows the binding destination; allowed arguments are passed unchanged. Both guards retain the eight-character registration minimum and lowercase/whitespace normalization; they do not track taint or detect paraphrases, other encodings such as base64 or unregistered values. Unregistered path/query values and remaining structured channels still require host constraints ([residual channels](security-review.md#brief-97-b-and-c-duties)). Restore conservatively registers every saved submission string before exposing pending props, because historical submissions have no schema identity. Values present only in prior run input, capability output or checkpoint state cannot be reconstructed by that check; without a recovery store there are no saved submission strings to register.
- Manifests and digests do not provide signatures, publisher authentication or proof of safe behavior when both package and manifest can be replaced ([manifest trust model](system-design.md#62-generated-agent-manifests)).
- Client budgets and cooperative cancellation do not enforce provider billing or backend authorization ([baseline limits](security-review.md#adr-0012-baseline)).
- galaxie ships no authentication or authorization library integration, and a client-side permission check is not backend authorization. Hosts attach their own session provider, client abilities and server policy engine to the existing seams ([identity and authorization](guides/host-integration.md#identity-and-authorization)).
- The output-safety hook covers routed reply text and tool-call arguments only, cannot retract already-allowed chunks, and does not cover direct models, capability results or every display callback ([output handling](security-review.md#owasp-top-10-for-llm-applications-2025)).
- Development warnings and lint rules are best-effort advice rather than runtime containment or exhaustive CSP/credential scans ([warnings](system-design.md#development-warnings), [lint limits](../packages/eslint-plugin/README.md)).

## Browser-built retrieval example

The [RAG example](../examples/rag-browser/README.md) offers LangGraph.js and optional LangGraph Python/pydantic-ai/DSPy builds. The pydantic-ai choice currently uses mock models and requires an answer-role provider declaring `tool-calling`. DSPy retrieves with program-owned arguments; with opt-in review it pauses before its first model call. It needs no tool calling, but its answer role needs a provider declaring `streaming`. Real-model ChatAdapter format reliability and its hands-on browser check remain unverified. Pending opt-in passage reviews restore on all four executors; default questions, answer displays and unsent review selections do not. Individual pasted-passage deletion and a prebuilt pinned-index format are absent. Python is omitted when the verified wheel cache is absent at build time. Its retrieval cache remains outside `@galaxie-ai/storage-indexeddb`, is scoped by app and principal, and is wiped by the principal-invalidation signal and Clear data; it has no retention sweep. The example has a constant `visitor` principal and no login, so end-to-end logout is not demonstrated; a real host must announce invalidation after its principal wipe. Concurrent builds can replace whole records; clear uses cross-tab invalidation and a durable content-free generation fence. Browser eviction loses the index. WebGPU is required for embeddings, with no WASM inference fallback. Full-corpus indexing, real-model retrieval/citation quality, reference-device performance and simultaneous embedding/chat GPU memory use remain unmeasured. The existing WebLLM context limit can reject large prompts. Python source is trusted and can reach Worker APIs through `js`; the lint aid and same-origin CSP do not make it an isolation boundary. Runtime assets and local build artifacts retain the page bundle's trust rather than an independent runtime SRI guarantee.

## ADK recipe example

The [ADK recipe host](../examples/adk-recipes/README.md) runs financial-advisor rewrites on JavaScript and Go, and auditor and loan rewrites on Python, with scripted mock models in every automated test. Free-text outside the page's scripted fixture defaults reports unverifiable. All companies, documents, market bulletins and pricing tiers are synthetic; outputs are not financial advice and must not be used for real lending decisions. One real-model demonstration on the maintainer's device is recorded separately ([record](adk-recipes-real-model-record.md)); it is not a measurement or an answer-quality claim.

One recipe and executor are active per page load. Switching aborts and disposes before a fresh page starts. Go and Python entries are unavailable without a built wasm or verified local wheel cache; the Vite build still succeeds without them. Mock mode downloads nothing. Default mode wires one reviewed ONNX record (Qwen3.5-0.8B q4, a 666 MB download behind the browser's own confirmation); LFM3 has no record. The [refused-shape table](../examples/adk-recipes/README.md#refused-shapes) records the `AgentTool` coordinator rewrites, omitted callbacks and cloud services, and the deliberately unrewritten safety-plugins recipe.

The loan's displayed decision comes only from its pending confirmation or finalize receipt; a text-only completion is undecided. Approval is followed by a separate broker finalization prompt. Scoped IndexedDB checkpoints and recovery restore a paused loan, and Start over deletes that session. Visible answer text and the other recipes do not restore. Fixture decision records remain host-memory data; this supplies no lending backend or cross-device resume. Reconciliation limits are listed under [storage and recovery](#storage-and-recovery).
