## Execution and LangGraph

- LangGraph.js routed `bindTools` and `host.langchain.capabilityTool` have mock-only scenarios on Node and Chromium, and no real-model result is claimed. The helper refuses to offer a write without `approval: 'confirm'` and host confirmation coverage. The ADK JavaScript helper and the Python `capability_tool` helpers (ADK, DSPy, pydantic-ai) apply the same rule: they refuse a capability that is not a read unless it is bound with `approval: 'confirm'` and the runtime has host confirmation coverage, and they refuse an unbound name, with the fixed `invalid` error. The ADK helpers return that error to the model as fixed text; the DSPy and pydantic-ai helpers end the run with it. The core broker's treatment of ordinary capability calls is unchanged, so a direct `capabilities.call` from agent code is not affected. The evidence is mock and in-process scenarios only. A declined confirmation returns fixed `denied` text and the model may request the write again, bounded by the tool-call budget. Output safety checks tool-call arguments and reply text, not tool-call names or IDs. A provider whose `bindTools` returns a wrapped runnable does not receive the routed destination marker. Custom author-built tools, including wrappers that replace a helper's declarations, are outside this guarantee: authors must preserve broker calls, labels, budgets, effect scopes and host confirmations. A native `ToolNode` must use `{ handleToolErrors: false }` so fatal broker failures end the run; the helper itself converts only `denied` and `invalid` into fixed model-visible messages. The full node config and deterministic per-task call order remain necessary for recovery ([tool helper](../packages/adapter-langgraph/README.md#model-chosen-capability-tools), [mock scenarios](../tests/conformance/langgraph-tools.test.ts)).
- Parallel interrupts and multiple interaction requests in one node remain unsupported in shipped code ([adapter limits](../packages/adapter-langgraph/AGENTS.md#limits)). The [Node spike](../spikes/parallel-interrupts/README.md) records parallel interrupts as **refused**: an answered no-state-write sibling retains a stale interrupt without a completion marker. Ask the questions before the fan-out, or chain interrupting branches so at most one task pauses per superstep, with one request per node. Several top-level requests in one node are **supported as a proven design, implementation pending review**; until that lands, split requests into separate nodes. Repeated child pauses and multi-pause/later-ordinal materialized surfaces remain refused. [Proposed ADR-0030](adr/0030-several-engine-pauses-published-one-at-a-time.md) records the obligations and limits; the [interrupt-sequence case](../tests/conformance/cases/interrupt-sequence.ts) proves the current author workaround.
- The [static-breakpoint/ID-less-interrupt spike](../spikes/static-breakpoints/README.md) records static breakpoints as **alternative**. Compiled `interruptBefore` and `interruptAfter` are refused at prepare, including `graph.config` and discoverable subgraphs, even for unreachable nodes. An invisible override ends the run `unsupported` at its first pause after preceding nodes ran. Use an explicit `requestInteraction` gate with continue/reject edges; the [replacement cases](../tests/conformance/README.md#static-breakpoint-refusal-and-gate-replacement) prove both actions and reload with memory and Chromium IndexedDB. Continue never replaces a host write confirmation. A synthesized static reject leaves its checkpoint paused and inbox accepted, so restore replays it; without the inbox the pause is republished. A single ID-less `requestInteraction` on a root checkpoint task now supports task-derived identity, bare resume and recovery on Node and Chromium, including a body-invoked child without a child checkpoint namespace. Compiled child namespaces, parallel/mixed pauses, unfinished siblings, repeated calls in one node, malformed requests/IDs and ID-less surfaces fail `unsupported`. Exact valid `NodeInterrupt`/raw `GraphInterrupt` requests publish once and fail on the first answer; with recovery, the accepted entry remains and restore retries the failure. A refused second call leaves the entry accepted and restore fails `executor_error`. Always pass complete node config. See [the shipped limits and registration scope](../packages/adapter-langgraph/README.md#id-less-interrupts) and [conformance evidence](../tests/conformance/README.md#id-less-interrupts). Second pauses inside body-invoked children, repeated child pauses, loop revisits and real models remain unmeasured. Static breakpoints remain unsupported; explicit gates are the alternative.
- Without a recovery store, a parent node's broker-bound write before an interrupting child repeats on resume. With recovery and the node config explicitly forwarded, the stable task scope replays the successful receipt: two parent bodies, one host write, including after IndexedDB reopen and restore. Call order within a task must be deterministic. Effects outside the broker still repeat; put side effects after interrupts or in a separate completed node ([parent-effect tests](../tests/conformance/subgraph-effects.test.ts), [scope and restore tests](../tests/conformance/subgraph-effect-scopes.test.ts), [AT-35](mvp-exit-record.md#acceptance-tests)).
- Implicit async LangChain context is unavailable under the synchronous shim; pass node config explicitly, and initialize real `AsyncLocalStorage` before the first prepare on Node when async ambient context is required ([context inventory and matrix](../tests/conformance/README.md#explicit-config-and-context)).
- LangGraph facades without native `transform()` or checkpoint `getState()` are unsupported ([adapter contract](system-design.md#6-core-runtime-and-contracts)).
- Universal Python execution, adapters beyond the implemented LangGraph.js and experimental LangGraph Python/pydantic-ai/DSPy paths, distributed agents, cross-device resume and always-on scheduling are outside the MVP ([scope](galaxie-project-brief.md#52-outside-the-mvp), [Python adapter](../packages/adapter-pyodide/README.md)).
- The JavaScript executor runs on the main thread; the experimental Python executor runs in a dedicated Pyodide Worker under the scoped exception in ADR-0018. Real-inference long tasks remain unmeasured ([execution context](adr/0003-executor-execution-context.md), [Python decision](adr/0018-python-agents-through-pyodide.md), [M2 measurements](m2-exit-record.md#not-measured)).
- LangGraph Python interrupts, resume and durable checkpoints are available. Reload restore requires the scoped IndexedDB byte-record port and recovery store; without that port, cancellation or Worker loss still discards in-memory state. LangGraph Python streaming and subgraphs are available, including child interrupts and durable restore. Its driver accepts asynchronous text model calls and checked streaming, with no tool-call or multimodal replies. Streamed calls require a provider declaring streaming, including implicit graph message streaming. Graph chunks must have bounded JSON projections; raw graph streams remain untrusted working state and are delivered live without replay. A checkpoint tuple or list must fit one 1 MiB bridge message after base64. RAG offers opt-in persistent passage review on both LangGraph executors, with mock Node/Chromium parity and reload coverage; the default flow stays in memory. A `pydantic-ai-python` executor runs pydantic-ai agents with tool calls, checked streaming and deferred-tool approval interactions; its conversation snapshots restore pending approvals after a fresh Worker and reopened scoped IndexedDB with the matching recovery store. Without the byte-record port, cancellation or Worker loss still discards pending state. Tool-less `NativeOutput` uses routed `jsonSchema` constraints, requires `structured-output`, and charges validation retries to the host route and shared run repair limits. Native output with tools, deferred requests or a string schema template is refused at prepare, as are callable agent settings and every agent setting except `stop_sequences`; later-contributed tools or settings are refused before the bridge. Provider-specific settings stay refused because provider selection, request shaping and output limits belong to the host. Multimodal content, builtin/native tools and arbitrary mid-run continuation remain unsupported. The [delegation probes](../tests/conformance/README.md#pydantic-ai-agent-delegation-probes) record an alternative for plain delegation and a successful explicit child-approval hoist with restore. The helper, hoist API and public-only nested-run guard remain probe-local; no run-time nested refusal ships yet. Plain child IDs break write replay, shared parent IDs collide, native children share repair accounting, and child stream paths remain absent, so `subgraphs` stays false. Prefer one agent with capability-backed tools. Browser delegation is unmeasured. Native-output evidence is scripted CPython, Node Pyodide and Chromium parity only; real-model constraint enforcement is unverified. The RAG example now offers it for mock tool-calling models, with deferred passage review, reload and Start over; its hands-on Chrome check remains unverified. The bundled WebLLM and Built-in AI providers do not declare tool calling, so default mode omits this choice. The tutor port remains unimplemented ([adapter limits](../packages/adapter-pyodide/README.md)).

- DSPy 3.4.1 custom-engine programs support checked streaming, replay-based interrupts/resume and durable journals; subgraphs remain false because nested modules have no checkpoint namespaces or interrupt/stream-path propagation. Author code must be deterministic apart from journaled model, capability and interaction calls; divergence fails `unrecoverable` before later live calls. Pauses must fit the 1 MiB bridge bound including base64; completion stores compact counters. Calls after the last committed pause can repeat after Worker loss; broker write deduplication requires recovery and stable call order. Restored input and journal results use core's framework-neutral `registerRestoredData` hook before URL validation or live outbound calls. This does not add that registration to other executors' histories.
- DSPy sync entry points, `dspy.Parallel`, threaded `Evaluate`, runtime optimizers, multimodal types, embeddings, service retrievers, provider-string LMs and native provider schema output are unsupported. Offline-optimized JSON state is verified on CPython, Node Pyodide and headless Chromium with scripted `LabeledFewShot`, scripted-LM `BootstrapFewShot`, ReAct multi-predictor demos and an instructions-only stand-in; see the [size bounds, load cost and round-trip catalog](../packages/adapter-pyodide/README.md#offline-optimized-program-state). MIPROv2, COPRO and GEPA output, real-model quality, pickle forms, other DSPy versions, Firefox/WebKit, Chromium load cost and device performance remain unverified. Paused-session state swaps are verified with scripted models on CPython, Node Pyodide and Chromium reloads through IndexedDB: a changed journaled request fails `unrecoverable` without live calls and poisons later restores, while swaps that leave the journaled requests unchanged complete under the new state. Including the state file SHA-256 in interaction props also refuses byte-only changes; see [the cases and author recipe](../packages/adapter-pyodide/README.md#paused-sessions-and-a-changed-state-file). JSONAdapter supports non-streaming prompted JSON only; `jiter` is absent from the Worker. ChatAdapter JSON fallback is disabled; parse errors end the run. An `Executor` with `stream_fields` always streams and requires a streaming provider and uniquely identified plain-`str` fields. Streaming ReActV2 needs `next_thought` annotated as `str`. Indented field headers are not streamed; final parsing still returns their value. ReAct author tool exceptions become observations with a five-frame traceback (file paths/source lines), carried by the next routed model call; galaxie failures instead terminate before that call with fixed codes. The Worker omits `litellm`, `openai`, `gepa`, `tenacity`, `diskcache` and `cachetools`; CPython's metadata-only `litellm==1.106.2` stand-in contains no module. See the [adapter limits](../packages/adapter-pyodide/README.md#dspy-programs).

## Google ADK (JavaScript)

- The `adk-js` executor (ADK 2.3.0, web bundle) accepts only `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent` trees whose models and tools come from the host. `AgentTool`, `Workflow`, `RemoteAgent`, built-in network tools, toolsets, code executors, author `BaseAgent` subclasses and string or `Gemini` models fail `unsupported` at prepare. Live and bidirectional streaming and multimodal parts are unsupported; stored records refuse binary parts.
- `subgraphs` is false: ADK sub-agent events carry `author` and `branch`, not LangGraph namespaces, and nested stream paths and nested-pause parity are not built. `AgentTool` could return only through an adapter-owned wrapper with its own run config, integrity plugin and session keying.
- A confirmation fails `unsupported` when it sits beside other calls in one model turn. Any pause fails `unsupported` in a tree that contains a `ParallelAgent`, inside a `LoopAgent`, in a later child of a `SequentialAgent`, under an `LlmAgent` that sits inside a workflow agent, or when the pausing agent's name is unknown or duplicated, because ADK restarts those workflow agents from their first child on resume and earlier siblings, with their writes, would run again. `adk_request_input` is unsupported. A pause in the first child at every `SequentialAgent` step, or anywhere in a chain of `LlmAgent`s linked by transfer, resumes in place.
- Durable sessions need the scoped byte-record port; without it conversations live in memory and a reload starts over. Each record is limited to 4 MiB and 10,000 events, and a longer conversation fails `unsupported` when it is stored. The per-session integrity key guards in-flight forgery and corrupt history, not a writer of the store. The reconcile hook is unmeasured through this executor; see [storage and recovery](#storage-and-recovery).
- ADK still emits content-free spans of its own to a registered global OpenTelemetry provider, and the adapter does not re-check a response that an agent-level model callback replaces (ADR-0002). Span content capture must be disabled by a build define. Worker-hosted runs, real model providers and the example host are unmeasured ([ADR-0020](adr/0020-google-adk-through-an-adapter.md), [adapter README](../packages/adapter-adk/README.md)).

## Google ADK (Python)

- The `adk-python` executor ([ADR-0022](adr/0022-google-adk-python-through-the-pyodide-adapter.md), `google-adk` 2.12.0 in the Pyodide Worker) runs `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent` trees whose models and tools come from `galaxie.adk`. Other agent types, string or `Gemini` models, toolsets, code executors, planners, plugins, `App` objects and the retry, timeout, schema and parallel-worker fields fail `unsupported` at prepare. Author callbacks run, but a callback that swallows a tool failure cannot keep the run going.
- `streaming`, `interrupts`, `resume` and `checkpoints` are on; `subgraphs` is false because ADK sub-agent events carry `author` and `branch`, not LangGraph namespaces: nested stream paths and sub-agent checkpoint namespaces are not built, and `AgentTool` could return only through an adapter-owned wrapper with its own run configuration, integrity plugin and session keying. `Workflow` and `AgentTool` run natively on ADK 2.12.0 and fail `unsupported` at prepare here. Sessions are stored as an event log through the byte-record port with a per-session integrity key beside it, so a reload restores a pending interaction, but a writer of the store can forge both; a record must fit one 1 MiB bridge frame (about 719 KB raw) and a run that would exceed it fails `unsupported` before the next dispatch. A run streams checked text deltas (`messages`, at most 4096 code points each) and content-free tool and `paused` markers (`updates`), and every model call is a streamed request, so the routed provider must declare `streaming`. Deltas already delivered are not retracted when a later chunk is blocked, and the stream is not journaled.
- A pause is a tool with `require_confirmation=True` (ADK's confirmation) or `long_running=True`. It ends the run and the answer is a new run. A uniquely named leaf may pause under `SequentialAgent` ancestors at any child position, including nested sequences; one pausing agent beneath each `ParallelAgent` may ask for confirmation. Newly enabled positions use ADK resumability; existing last-child sequences keep the original runner. Pauses under a `LoopAgent` stay refused because native resumability repeats a finished tool in a writer/checker loop, even though a bare worker continues. Multiple pausing agents under a Parallel ancestor, long-running tools under a Parallel ancestor, unknown or duplicate pausing names, pausing agents with children and pauses under an `LlmAgent` parent fail `unsupported` at prepare. Resumable apps also refuse duplicate names anywhere, `temp:` output keys and any `LlmAgent` with transfer children: progress is keyed by name, temporary state is lost and resumable transfer routing is unproven. Long-running Parallel pauses remain refused because interleaved calls can reset the single long-running tracker. A resumable app allows one pausing agent in total and refuses an exit tool beneath a `ParallelAgent`, because a second pausing agent is unproven under resumability and an escalation cancels sibling branches. See the [workflow-agent pause evidence](adr/0022-google-adk-python-through-the-pyodide-adapter.md#workflow-agent-pause-spike-2026-11).
- A confirmation beside a long-running call in one model turn fails `unsupported` before any tool runs; a pausing tool without an `interaction` hook fails `unsupported` at prepare. A new prompt while a pause is pending fails `invalid`. The default resume covers only confirmations with `approve` or `deny` and payload `{ indexes }`; a long-running call needs the author's `resume` hook, and every pending request must be answered at once. A failed resume keeps the pause; with durable recovery, core retries an already accepted answer and succeeded write receipts prevent another host invocation. Without recovery, the approved capability can run again. Cancelling or aborting a run drops the in-memory pause.
- Input is `{ prompt: string }`. Replies and tool results with non-text parts fail `unsupported`. The lint aid rejects every `google.genai` import, so author code cannot import `google.genai.types` yet.
- Python is trusted and can import `js`; the tree validation and lint aid reduce accidents and are not a boundary. Only the third-party wheels have independent hash checks. Evidence is scripted models on Node and headless Chromium, with an injected-fetch credential scan on Node: no real model, device measurement of the 29-wheel boot (about 12.6 MB), memory or first-token cost, third-party endpoint or external developer trial exists.
- ADK's `SequentialAgent`, `ParallelAgent` and `LoopAgent` emit `DeprecationWarning` in 2.12.0; confirmation, agent state and `ResumabilityConfig` are experimental. Temporary (`temp:`) state from before a pause is unavailable after resume. A later release may change or remove these features, so a version bump re-runs the shape and workflow-pause cases. Author callbacks run in trusted Python and are not re-checked, and the adapter does not re-check a response an agent-level callback replaces (ADR-0002).
- Parallel branches that call write capabilities get branch-local effect scopes and replay their receipts when the same prompt re-dispatches them in another order. Branch scopes rely on ADK 2.12.0 naming each branch after its agent path; hosts need the recovery store for writes to deduplicate. The reconcile hook is unmeasured through this executor; see [storage and recovery](#storage-and-recovery).

## Google ADK (Go)

- The `adk-go` executor ([ADR-0023](adr/0023-google-adk-go-through-a-wasm-worker.md), `google.golang.org/adk` v1.9.0 compiled to WebAssembly in a dedicated Worker) runs agent trees built only with the galaxie Go constructors: `LlmAgent`, `SequentialAgent`, `ParallelAgent`, `LoopAgent`, `ExitLoop`, `Model` and `CapabilityTool`. These shapes fail `unsupported` at prepare or when the run starts: `agenttool` and any other agent wrapped as a tool; an agent, model, function tool or toolset made directly with ADK instead of the galaxie constructors; a tree deeper than 16 levels; and a loop with neither an iteration limit nor an exit tool. A capability whose tool name equals ADK's confirmation call name is refused.
- `streaming`, `interrupts`, `resume` and `checkpoints` are on; `subgraphs` is false because ADK sub-agent events carry `author` and `branch`, not LangGraph namespaces, so nested stream paths, nested-pause parity and sub-agent checkpoint namespaces are not built. Go receives one aggregated reply per model call; the page checks and forwards the text as it grows.
- A pause (a confirmation or a long-running tool) fails `unsupported` inside a `ParallelAgent` or `LoopAgent`, in any `SequentialAgent` child other than the last, when the pausing agent's name is not unique, when a confirmation sits beside a long-running call in one turn, and when a pausing tool has no `Interaction` hook, because ADK resumes only the agent that paused and would skip the siblings. A pause in a transfer target or in the last child of a sequence resumes in place. Parallel write branches get branch-local effect scopes, so arrival order does not matter. A run that fails without ever pausing stores no record and core refuses to start an adopted session, so a new runtime cannot continue it and its next session writes again. A restore after a pause that follows a Parallel stage resumes only the pausing agent, so no branch write runs again.
- Go is trusted author code. It can call `syscall/js` and `net/http`; the loader's throwing stubs and the CSP `connect-src` catch accidental network use, but the stubs are not an isolation boundary. Agent-level callbacks (before and after model, tool and agent) are trusted author code: a callback that returns its own response replaces a model call and skips routing, labels and the output check (ADR-0002). The wasm is the author's build, bound to the reviewed bytes by length and SHA-256; the lock hashes the copied `wasm_exec.js` source, not the bundler's output, and no Go-side integrity plugin exists.
- The module is about 30 MB stripped (about 6.5 MB gzip) and is not size-reduced: TinyGo is rejected and `wasm-opt` is not run. Boot, compile, memory and first-token cost are measured only on the maintainer's machine (Go ready after about 95 ms with scripted models); no real-device cold start, real model, third-party endpoint or external developer trial exists.
- Durable sessions need the scoped byte-record port as `services.checkpoints`; without it a pause lives only as long as its Worker. A record is capped at 512 KiB, below the 1 MiB bridge frame, and the size guard counts stored events only, so a very large pause or answer can still fail late (the previous revision stays current and the pause stays answerable). Every run writes a full new revision, reclaimed only by the retention sweep.
- The record's HMAC-SHA-256 tag covers the session id, revision id, stream position and record bytes. It detects corruption, truncation, splicing between sessions and accidental or blind misplacement of a record between revision slots. The key sits beside the record, so anyone who can read and write the store can recompute the tag. Restoring an earlier valid revision after newer ones were removed is not detected, and a key held outside the store is not built. The format is unpublished, so no migration was needed; a record from an earlier development build restores as `unrecoverable`. Keep the store on-device under the checkpointer's scope with one active owner per session.
- Pair `services.checkpoints` with core's `recovery` store whenever a write capability is bound: a resume that fails after an approved write re-offers the same pause, and without recovery the write can run twice. A retried resume replays a model that may not be deterministic and can re-emit stream indices. State-delta values come back as JSON types (numbers as floats, maps and lists generic) after a reload. The reconcile hook is unmeasured through this executor; see [storage and recovery](#storage-and-recovery).
- Streaming limits: the queue applies backpressure at 256 events. The output check hook receives the cumulative reply on every chunk, so the hook's own cost grows with reply length. For a reply that carries tool calls, the adapter still rebuilds the checked text from the joined message on each chunk. The `ParallelAgent` and `LoopAgent` shapes and the confirmation feature are what ADK v1.9.0 ships; a later ADK release may change them, and a version bump re-runs the shape cases.

## Models and providers

- A route's `maxTokens` reservation reaches the WebLLM, Transformers and OpenAI-compatible models as the per-call output limit (the lower of it and the provider's own limit), and the LangGraph, Pyodide, ADK JavaScript and ADK Go adapters forward it. Built-in AI has no output limit and ignores it, an OpenAI-compatible call with no limit set anywhere sends none, and actual usage can still differ from the reservation ([model contract](system-design.md#84-a-model-call)).
- SDK-supplied download-consent UI remains unimplemented; hosts supply consent/download interaction. Structured-output repair is disabled by default and requires host opt-in through `ModelRoute.repairAttempts`, bounded by the shared run budget. Direct provider-level repair and real-model repair rates remain outside this slice ([provider limits](system-design.md#84-a-model-call)).
- Cached WebLLM weights do not imply a loaded engine, and lazy routed construction still requires host preparation ([model guidance](../packages/models/AGENTS.md#limits), [model flow](system-design.md#84-a-model-call)).
- WebLLM resets context for every queued request rather than reusing a conversation's KV cache, and worker/device failure requires a new handle, model and runtime ([model flow](system-design.md#84-a-model-call)).
- Built-in AI is page-only, reports neither per-call token usage nor download byte size, ignores `maxTokens` and temperature, and has a browser-managed model identity that cannot be pinned ([provider contract](system-design.md#84-a-model-call)).
- A failed dispatched model call is not silently retried on another provider, and real remote-provider and localhost/LNA deployments remain unverified ([provider contract](system-design.md#84-a-model-call), [device gaps](device-matrix.md#untested-or-unmeasured)).
- The ONNX provider (`@galaxie-ai/models/transformers`, [ADR-0021](adr/0021-in-browser-onnx-chat-provider.md)) ships no default model record: a maintainer pins each candidate with `scripts/pin-onnx-model.ts`, and one record is pinned, for the adk-recipes example only (Qwen3.5-0.8B q4; LFM3 is unpinned). Its automated tests use a fake runtime; the only real-model evidence is one demonstration on the maintainer's device ([record](adk-recipes-real-model-record.md): one run per recipe and one clean-profile first download), so output quality, tool-call reliability rates, memory and speed are unmeasured; Spike B saw degenerate Qwen2.5 `q4f16` text and a `q4` allocation failure on Transformers.js 4.3.1 (reference only). The package pins Transformers.js 4.3.2, which adds the LFM3 architecture; Qwen3.5 and LFM3 tokenizer templates have XML rendering fixtures, but real-model tool-call reliability is unmeasured, and replies longer than its 256-token sliding window have run only in a reference-only spike with its own ONNX Runtime loop (quality not scored), never through this provider. The maintainer plans to use LFM weights, which carry the LFM Open License v1.0 (terms not reviewed here), only for non-commercial experimentation with galaxie.
- The ONNX provider never falls back from WebGPU to WASM; the record names one device. It runs one request at a time, and a model run cannot be interrupted, so abort latency is unbounded inside a run while the page rejects at once; a prompt of more than 256 tokens runs in 256-token slices and an abort is honoured between them (not measured on a device). A hung WebGPU decode raises no error and has no watchdog. Context is not reused between requests.
- ONNX tool calling is a text format (`hermes` JSON or `xml` function/parameter markup) declared by the record: the provider holds markup back from streamed reply text, converts XML scalars only on exact schema-directed round trips, and fails `unsupported` for any `tool_choice` that forces a call. The pin step detects formats from rendered calls and omits the format for unknown syntax. Text-only split exports select `embed_tokens` and `decoder_model_merged` plus their shards, excluding vision/audio encoders; this has fake-runtime evidence only. Structured output needs the optional constraint package, supports one sequence at a time, cannot share a request with tools, and rejects schemas with `pattern` or `format`; its first call builds tokenizer tables at an unmeasured cost.
- OpenAI-compatible calls support text, schema output and explicitly bound tools, with mock/loopback coverage only and no real-endpoint or real-model result claimed. Tool and structured-output requests cannot share one call; replies are capped at 16 tool calls. Hosts must declare `tool-calling` for routed providers. Keyless endpoints still have no Authorization-removal mode ([tool behavior](../packages/models/README.md#openai-compatible-tools), [provider contract](system-design.md#84-a-model-call)).

## Storage and recovery

- An optional binding hook, `reconcile(effectId, context)`, can resolve a restored `dispatched` or `outcome_unknown` write with `retry: 'none'` ([ADR-0029](adr/0029-reconcile-hook-for-unknown-outcome-writes.md)). Core consults it once per restored call, before approval, with the abort signal but no call input. `applied` with an output settles `succeeded` through the usual schema validation, payload bound and labels, without invoking or approval. `not-applied` replays under the same effect ID with fresh approval where required. `unknown`, throws, rejections and malformed answers fail `outcome_unknown`. A consult exceeding `timeoutMs` fails `timeout` in either approval mode; cancellation or disposal fails `cancelled`. These failures leave the receipt `outcome_unknown`. Without a hook, behavior is unchanged: the write stays blocked and the host reconciles outside the framework before starting a potentially repeating operation.

  The host's `not-applied` answer must mean no request sent before the answer can still apply that effect ID, while the replay that core sends next is admitted (for example by refusing earlier owner generations). An absence check cannot exclude a late request from a former owner ([ADR-0009](adr/0009-multi-tab-ownership.md)). Core cannot verify the answer; a false `not-applied` can repeat a write.

  Measured: [core unit tests](../packages/core/test/reconcile.test.ts) cover binding validation, applied schema/payload/label checks and private values, replay and timeout in both approval modes, fail-closed answers, cancellation, disposal, one consult per restored call and unchanged behavior without a hook. [Conformance](../tests/conformance/reconcile.test.ts) uses LangGraph and an in-test mock backend on Node with memory storage and Chromium with IndexedDB reopened between runtimes. The broker is executor-neutral by construction, but the hook is unmeasured through ADK JavaScript, ADK Python, ADK Go, Pyodide and DSPy; DSPy keeps its own Python-side replay journal. Firefox, WebKit, real backends (including real HTTP backends) and host answer soundness are unmeasured.
- For an `httpCapability` declared `retry: 'idempotency-key'`, the effect ID is sent as the `Idempotency-Key` header, so a backend that deduplicates on it makes a repeat safe; galaxie does not guarantee the backend does, and the evidence is injected-fetch and loopback only ([effect recovery](system-design.md#83-a-capability-call)).
- Recovery data is not migrated across builds. Session, submission and effect records carry `formatVersion` (current value `1`); records without it, including the 0.1.0 shape, read as version 1. A newer version fails closed with a clear error (`newer_record` from IndexedDB, mapped to `unrecoverable` on restore). The stamp cannot distinguish unstamped receipts keyed by run segment from task-scoped ones. Write receipts recorded before task-scoped effect IDs are keyed by run segment, and a newer build cannot find them, so resuming such a session on a newer build can repeat a write, including a `retry: 'none'` write. No migration exists. Hosts must resume with the build that created it, or Start over and reconcile with the backend by effect ID before upgrading. A 0.1.0 build reads stamped records as corrupt because it enforces strict key counts, so hosts must not roll back across this change while sessions are pending. A host that talks to the IndexedDB saver directly must not offer "Start over" for a `newer_record` failure; retain the data and resume with a build that supports its format. `restore()` reports a newer IndexedDB record as the same generic `unrecoverable` error as a corrupt one, so a host that only sees the restore error cannot tell them apart yet, and the host-local example offers Start over for both ([recovery contract](system-design.md#82-reload-and-crash-recovery)).
- Reload recovery cannot finish an arbitrary intermediate checkpoint with no pending interrupt or replay later writes from that point ([recovery limits](system-design.md#82-reload-and-crash-recovery)).
- The checkpoint saver's `exportSession` supplies content-free metadata by default and personal checkpoint content only with exact `personalContent: true`, which hosts must bind to an explicit user action. Host-local wires a metadata-summary download and a host-confirmed personal-content download; host-remote has no export UI. Export is lossy and supplies no import, sync, cross-device recovery or durable runtime-event history ([export semantics](../packages/storage-indexeddb/README.md#explicit-session-export), [scope](galaxie-project-brief.md#52-outside-the-mvp)).
- IndexedDB storage is not encrypted by the package and browser persistence is not permanence, so eviction can return a fresh start ([storage limits](../packages/storage-indexeddb/AGENTS.md#limits)).
- Ownership and logout need host composition, cannot fence a tab that bypasses ownership, and cannot undo an already-sent remote effect ([ownership](system-design.md#85-tab-ownership-and-takeover), [logout](system-design.md#86-logout)).

## Tools and MCP

- Third-party MCP servers and OAuth flows are unsupported; only host-controlled servers or gateways with configured principal credentials belong to this profile ([MCP scope](../packages/tools-mcp/README.md)).
- MCP resources, prompts, sampling, elicitation, roots, resumable streams and automatic model tool discovery are not exposed ([MCP profile](system-design.md#61-mcp-client), [client limits](../packages/tools-mcp/AGENTS.md#limits)).
- Runtime pin approval is not provided, and metadata pins detect changed definitions rather than changed behavior behind an unchanged definition ([pinning contract](../packages/tools-mcp/README.md)).
- Each principal uses one serial MCP client lane even when a binding permits greater concurrency, with a fresh listing before dispatch and no stream resumption ([client limits](../packages/tools-mcp/README.md)).
- Generic fetch, SQL and shell capabilities are not provided, and a write without the required host confirmation configuration fails `unsupported` ([broker flow](system-design.md#83-a-capability-call)).

## Security boundaries

- Trusted-first execution supplies no sandbox for arbitrary JavaScript, unreviewed agents or same-origin dependencies, which can bypass SDK-controlled paths ([trust boundary](security-review.md)).
- Data labels do not detect paraphrases sent to allowed destinations. Core rejects interaction URL candidates containing registered private strings in raw or twice percent-decoded form, with `+` treated as a space, unless `private-user` policy allows `third-party`. Parser-normalized candidates receive the same checks, including tab/newline/carriage-return stripping. When whole-URL decoding fails, each maximal run of valid percent escapes is decoded independently; invalid UTF-8 runs stay raw. The broker applies the same raw and twice-decoded matching to every argument string and key, including structured fields, only when private-user policy disallows the binding destination; allowed arguments are passed unchanged. Both guards retain the eight-character registration minimum and lowercase/whitespace normalization; they do not track taint or detect paraphrases, other encodings such as base64 or unregistered values. Unregistered path/query values and remaining structured channels still require host constraints ([residual channels](security-review.md#brief-97-b-and-c-duties)). Restore conservatively registers every saved submission string before exposing pending props, because historical submissions have no schema identity. Values present only in prior run input, capability output or checkpoint state cannot be reconstructed by that check; without a recovery store there are no saved submission strings to register.
- Manifests and digests do not provide signatures, publisher authentication or proof of safe behavior when both package and manifest can be replaced ([manifest trust model](system-design.md#62-generated-agent-manifests)).
- Client budgets and cooperative cancellation do not enforce provider billing or backend authorization ([baseline limits](security-review.md#adr-0012-baseline)).
- galaxie ships no authentication or authorization library integration, and a client-side permission check is not backend authorization. Hosts attach their own session provider, client abilities and server policy engine to the existing seams ([identity and authorization](guides/host-integration.md#identity-and-authorization)).
- The output-safety hook covers routed reply text and tool-call arguments only, cannot retract already-allowed chunks, and does not cover direct models, capability results or every display callback ([output handling](security-review.md#owasp-top-10-for-llm-applications-2025)).
- Development warnings and lint rules are best-effort advice rather than runtime containment or exhaustive CSP/credential scans ([warnings](system-design.md#development-warnings), [lint limits](../packages/eslint-plugin/README.md)).

## Browser-built retrieval example

The [RAG example](../examples/rag-browser/README.md) offers LangGraph.js and optional LangGraph Python/pydantic-ai/DSPy builds. The pydantic-ai choice currently uses mock models and requires an answer-role provider declaring `tool-calling`. DSPy retrieves with program-owned arguments; with opt-in review it pauses before its first model call. It needs no tool calling, but its answer role needs a provider declaring `streaming`. Real-model ChatAdapter format reliability and its hands-on browser check remain unverified. Pending opt-in passage reviews restore on all four executors; default questions, answer displays and unsent review selections do not. Individual pasted-passage deletion and a prebuilt pinned-index format are absent. Python is omitted when the verified wheel cache is absent at build time. Its retrieval cache remains outside `@galaxie-ai/storage-indexeddb`, is scoped by app and principal, and is wiped by the principal-invalidation signal and Clear data; it has no retention sweep. The example has a constant `visitor` principal and no login, so end-to-end logout is not demonstrated; a real host must announce invalidation after its principal wipe. Concurrent builds can replace whole records; clear uses cross-tab invalidation and a durable content-free generation fence. Browser eviction loses the index. WebGPU is required for embeddings, with no WASM inference fallback. Full-corpus indexing, real-model retrieval/citation quality, reference-device performance and simultaneous embedding/chat GPU memory use remain unmeasured. The existing WebLLM context limit can reject large prompts. Python source is trusted and can reach Worker APIs through `js`; the lint aid and same-origin CSP do not make it an isolation boundary. Runtime assets and local build artifacts retain the page bundle's trust rather than an independent runtime SRI guarantee.

## ADK recipe example

The [ADK recipe host](../examples/adk-recipes/README.md) runs financial-advisor rewrites on JavaScript and Go, and auditor and loan rewrites on Python, with scripted mock models in every automated test. Free-text outside the page's scripted fixture defaults reports unverifiable. All companies, documents, market bulletins and pricing tiers are synthetic; outputs are not financial advice and must not be used for real lending decisions. One real-model demonstration on the maintainer's device is recorded separately ([record](adk-recipes-real-model-record.md)); it is not a measurement or an answer-quality claim.

One recipe and executor are active per page load. Switching aborts and disposes before a fresh page starts. Go and Python entries are unavailable without a built wasm or verified local wheel cache; the Vite build still succeeds without them. Mock mode downloads nothing. Default mode wires one reviewed ONNX record (Qwen3.5-0.8B q4, a 666 MB download behind the browser's own confirmation); LFM3 has no record. The [refused-shape table](../examples/adk-recipes/README.md#refused-shapes) records the `AgentTool` coordinator rewrites, omitted callbacks and cloud services, and the deliberately unrewritten safety-plugins recipe.

The loan's displayed decision comes only from its pending confirmation or finalize receipt; a text-only completion is undecided. Approval is followed by a separate broker finalization prompt. Scoped IndexedDB checkpoints and recovery restore a paused loan, and Start over deletes that session. Visible answer text and the other recipes do not restore. Fixture decision records remain host-memory data; this supplies no lending backend or cross-device resume. Reconciliation limits are listed under [storage and recovery](#storage-and-recovery).
