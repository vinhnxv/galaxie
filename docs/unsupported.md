# Unsupported features and unverified paths

Checked against the implementation on 2026-10-31; the
[MVP exit record](mvp-exit-record.md) maps acceptance requirements to existing
evidence, with the maintainer's decision pending.

## Execution and LangGraph

- Parallel interrupts, static breakpoints, ID-less interrupts and multiple interaction requests in one node are unsupported ([adapter limits](../packages/adapter-langgraph/AGENTS.md#limits)).
- Without a recovery store, a parent node's broker-bound write before an interrupting child repeats on resume. With recovery and the node config explicitly forwarded, the stable task scope replays the successful receipt: two parent bodies, one host write, including after IndexedDB reopen and restore. Call order within a task must be deterministic. Effects outside the broker still repeat; put side effects after interrupts or in a separate completed node ([parent-effect tests](../tests/conformance/subgraph-effects.test.ts), [scope and restore tests](../tests/conformance/subgraph-effect-scopes.test.ts), [AT-35](mvp-exit-record.md#acceptance-tests)).
- Implicit async LangChain context is unavailable under the synchronous shim; pass node config explicitly, and initialize real `AsyncLocalStorage` before the first prepare on Node when async ambient context is required ([context inventory and matrix](../tests/conformance/README.md#explicit-config-and-context)).
- LangGraph facades without native `transform()` or checkpoint `getState()` are unsupported ([adapter contract](system-design.md#6-core-runtime-and-contracts)).
- Universal Python execution, adapters beyond the implemented LangGraph.js and experimental LangGraph Python/pydantic-ai/DSPy paths, distributed agents, cross-device resume and always-on scheduling are outside the MVP ([scope](galaxie-project-brief.md#52-outside-the-mvp), [Python adapter](../packages/adapter-pyodide/README.md)).
- The JavaScript executor runs on the main thread; the experimental Python executor runs in a dedicated Pyodide Worker under the scoped exception in ADR-0018. Real-inference long tasks remain unmeasured ([execution context](adr/0003-executor-execution-context.md), [Python decision](adr/0018-python-agents-through-pyodide.md), [M2 measurements](m2-exit-record.md#not-measured)).
- LangGraph Python interrupts, resume and durable checkpoints are available. Reload restore requires the scoped IndexedDB byte-record port and recovery store; without that port, cancellation or Worker loss still discards in-memory state. LangGraph Python streaming and subgraphs are available, including child interrupts and durable restore. Its driver accepts asynchronous text model calls and checked streaming, with no tool-call or multimodal replies. Streamed calls require a provider declaring streaming, including implicit graph message streaming. Graph chunks must have bounded JSON projections; raw graph streams remain untrusted working state and are delivered live without replay. A checkpoint tuple or list must fit one 1 MiB bridge message after base64. RAG offers opt-in persistent passage review on both LangGraph executors, with mock Node/Chromium parity and reload coverage; the default flow stays in memory. A `pydantic-ai-python` executor runs pydantic-ai agents with tool calls, checked streaming and deferred-tool approval interactions; its conversation snapshots restore pending approvals after a fresh Worker and reopened scoped IndexedDB with the matching recovery store. Without the byte-record port, cancellation or Worker loss still discards pending state. Subgraphs, `NativeOutput`, multimodal content, builtin/native tools, provider-specific settings and arbitrary mid-run continuation remain unsupported. The RAG example now offers it for mock tool-calling models, with deferred passage review, reload and Start over; its hands-on Chrome check remains unverified. The bundled WebLLM and Built-in AI providers do not declare tool calling, so default mode omits this choice. The tutor port remains unimplemented ([adapter limits](../packages/adapter-pyodide/README.md)).

- DSPy 3.4.1 custom-engine programs support checked streaming, replay-based interrupts/resume and durable journals; subgraphs remain false because nested modules have no checkpoint namespaces or interrupt/stream-path propagation. Author code must be deterministic apart from journaled model, capability and interaction calls; divergence fails `unrecoverable` before later live calls. Pauses must fit the 1 MiB bridge bound including base64; completion stores compact counters. Calls after the last committed pause can repeat after Worker loss; broker write deduplication requires recovery and stable call order. Restored input and journal results use core's framework-neutral `registerRestoredData` hook before URL validation or live outbound calls. This does not add that registration to other executors' histories.
- DSPy sync entry points, `dspy.Parallel`, threaded `Evaluate`, runtime optimizers, multimodal types, embeddings, service retrievers, provider-string LMs and native provider schema output are unsupported. Offline-optimized state loading is untested. JSONAdapter supports non-streaming prompted JSON only; `jiter` is absent from the Worker. ChatAdapter JSON fallback is disabled; parse errors end the run. An `Executor` with `stream_fields` always streams and requires a streaming provider and uniquely identified plain-`str` fields. Streaming ReActV2 needs `next_thought` annotated as `str`. Indented field headers are not streamed; final parsing still returns their value. ReAct author tool exceptions become observations with a five-frame traceback (file paths/source lines), carried by the next routed model call; galaxie failures instead terminate before that call with fixed codes. The Worker omits `litellm`, `openai`, `gepa`, `tenacity`, `diskcache` and `cachetools`; CPython's metadata-only `litellm==1.106.2` stand-in contains no module. See the [adapter limits](../packages/adapter-pyodide/README.md#dspy-programs).

## Google ADK (JavaScript)

- The `adk-js` executor (ADK 2.3.0, web bundle) accepts only `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent` trees whose models and tools come from the host. `AgentTool`, `Workflow`, `RemoteAgent`, built-in network tools, toolsets, code executors, author `BaseAgent` subclasses and string or `Gemini` models fail `unsupported` at prepare. Live and bidirectional streaming and multimodal parts are unsupported; stored records refuse binary parts.
- `subgraphs` is false: ADK sub-agent events carry `author` and `branch`, not LangGraph namespaces, and nested stream paths and nested-pause parity are not built. `AgentTool` could return only through an adapter-owned wrapper with its own run config, integrity plugin and session keying.
- A confirmation fails `unsupported` when it sits beside other calls in one model turn. Any pause fails `unsupported` in a tree that contains a `ParallelAgent`, inside a `LoopAgent`, in a later child of a `SequentialAgent`, under an `LlmAgent` that sits inside a workflow agent, or when the pausing agent's name is unknown or duplicated, because ADK restarts those workflow agents from their first child on resume and earlier siblings, with their writes, would run again. `adk_request_input` is unsupported. A pause in the first child at every `SequentialAgent` step, or anywhere in a chain of `LlmAgent`s linked by transfer, resumes in place.
- Durable sessions need the scoped byte-record port; without it conversations live in memory and a reload starts over. Each record is limited to 4 MiB and 10,000 events, and a longer conversation fails `unsupported` when it is stored. The per-session integrity key guards in-flight forgery and corrupt history, not a writer of the store. Unknown-outcome writes have no reconciliation API, as for the other executors.
- ADK still emits content-free spans of its own to a registered global OpenTelemetry provider, and the adapter does not re-check a response that an agent-level model callback replaces (ADR-0002). Span content capture must be disabled by a build define. Worker-hosted runs, real model providers and the example host are unmeasured ([ADR-0020](adr/0020-google-adk-through-an-adapter.md), [adapter README](../packages/adapter-adk/README.md)).

## Google ADK (Python)

- The `adk-python` executor ([ADR-0022](adr/0022-google-adk-python-through-the-pyodide-adapter.md), `google-adk` 2.12.0 in the Pyodide Worker) runs `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent` trees whose models and tools come from `galaxie.adk`. Other agent types, string or `Gemini` models, toolsets, code executors, planners, plugins, `App` objects and the retry, timeout, schema and parallel-worker fields fail `unsupported` at prepare. Author callbacks run, but a callback that swallows a tool failure cannot keep the run going.
- `streaming`, `interrupts` and `resume` are on; `checkpoints` and `subgraphs` are false, so a reload starts over and a pending interaction does not survive it (stage AP5 adds durable sessions). A run streams checked text deltas (`messages`, at most 4096 code points each) and content-free tool and `paused` markers (`updates`), and every model call is a streamed request, so the routed provider must declare `streaming`. Deltas already delivered are not retracted when a later chunk is blocked, and the stream is not journaled.
- A pause is a tool with `require_confirmation=True` (ADK's confirmation, experimental in 2.12.0) or `long_running=True`. It ends the run and the answer is a new run. A confirmation beside a long-running call in one model turn fails `unsupported` before any tool runs, and an executor with a pausing tool but no `interaction` hook fails `unsupported` at prepare. A pause fails `unsupported` at prepare inside a `ParallelAgent` or `LoopAgent`, when the pausing agent's name is unknown or duplicated, in any `SequentialAgent` child other than the last to run, and (conservatively) when the pausing agent has sub-agents or sits under an `LlmAgent` parent. A new prompt while a pause is pending fails `invalid`. The default resume covers only confirmations with `approve` or `deny` and payload `{ indexes }`; a long-running call needs the author's `resume` hook, and every pending request must be answered at once. A failed resume keeps the pause, and a retry runs the approved capability again, so writes need the host's recovery store; cancelling or aborting a run drops the in-memory pause.
- Input is `{ prompt: string }`. Replies and tool results with non-text parts fail `unsupported`. The lint aid rejects every `google.genai` import, so author code cannot import `google.genai.types` yet.
- Python is trusted and can import `js`; the tree validation and lint aid reduce accidents and are not a boundary. Evidence is scripted models on Node and headless Chromium only: no real model, credential scan or device measurement exists.

## Models and providers

- Router token reservations do not set per-call provider output caps, which remain deferred even though WebLLM and OpenAI-compatible providers have their own output-limit options ([model contract](system-design.md#84-a-model-call)).
- SDK-supplied download-consent UI remains unimplemented; hosts supply consent/download interaction. Structured-output repair is disabled by default and requires host opt-in through `ModelRoute.repairAttempts`, bounded by the shared run budget. Direct provider-level repair and real-model repair rates remain outside this slice ([provider limits](system-design.md#84-a-model-call)).
- Cached WebLLM weights do not imply a loaded engine, and lazy routed construction still requires host preparation ([model guidance](../packages/models/AGENTS.md#limits), [model flow](system-design.md#84-a-model-call)).
- WebLLM resets context for every queued request rather than reusing a conversation's KV cache, and worker/device failure requires a new handle, model and runtime ([model flow](system-design.md#84-a-model-call)).
- Built-in AI is page-only, reports neither per-call token usage nor download byte size, ignores `maxTokens` and temperature, and has a browser-managed model identity that cannot be pinned ([provider contract](system-design.md#84-a-model-call)).
- A failed dispatched model call is not silently retried on another provider, and real remote-provider and localhost/LNA deployments remain unverified ([provider contract](system-design.md#84-a-model-call), [device gaps](device-matrix.md#untested-or-unmeasured)).
- The ONNX provider (`@galaxie/models/transformers`, [ADR-0021](adr/0021-in-browser-onnx-chat-provider.md)) ships no default model record: a maintainer pins each candidate with `scripts/pin-onnx-model.ts` and none is pinned yet. It has fake-runtime evidence only, so real-model output quality, tool-call reliability with a real chat template, download size and time, memory and speed are unmeasured; Spike B saw degenerate Qwen2.5 `q4f16` text and a `q4` allocation failure on Transformers.js 4.3.1 (reference only).
- The ONNX provider never falls back from WebGPU to WASM; the record names one device. It runs one request at a time, and prefill cannot be interrupted, so abort latency on a long prompt is unbounded while the page rejects at once. A hung WebGPU decode raises no error and has no watchdog. Context is not reused between requests.
- ONNX tool calling is a text format (`hermes`) declared by the record: the provider drops tool markup from the reply text and fails `unsupported` for any `tool_choice` that forces a call. Structured output needs the optional constraint package, supports one sequence at a time, cannot share a request with tools, and rejects schemas with `pattern` or `format`; its first call builds tokenizer tables at an unmeasured cost.
- OpenAI-compatible calls support text and schema output rather than tool calling, and keyless endpoints have no Authorization-removal mode ([provider contract](system-design.md#84-a-model-call)).

## UI

- Draft persistence is not provided: component-local quiz and writing drafts reset on remount or reload ([React limits](../packages/react/AGENTS.md#limits)).
- Model-produced HTML, JavaScript and event handlers are not an accepted UI format; model props render as React text through trusted registry components ([React rules](../packages/react/AGENTS.md#never)).
- LLM-composed UI, additional renderer protocols and multiple renderers are outside this MVP ([scope](galaxie-project-brief.md#52-outside-the-mvp)).
- Payments, password changes and account deletion are excluded from agent-driven interactions, and catalogs must not collect passwords or payment credentials ([mandatory baseline](galaxie-project-brief.md#97-mandatory-security-baseline-invariant-adr-0012), [React rules](../packages/react/AGENTS.md#never)).

## Storage and recovery

- There is no unknown-outcome reconciliation API: an unknown `retry: 'none'` write remains blocked on restore, and the host must reconcile with its backend by effect ID before starting a potentially repeating operation ([effect recovery](system-design.md#83-a-capability-call)).
- Recovery data is not migrated across builds. Write receipts recorded before task-scoped effect IDs are keyed by run segment, and a newer build cannot find them, so resuming such a session on a newer build can repeat a write, including a `retry: 'none'` write. No package has been released yet. Hosts must resume a session with the build that created it, or Start over and reconcile with the backend by effect ID before upgrading ([recovery contract](system-design.md#82-reload-and-crash-recovery)).
- Reload recovery cannot finish an arbitrary intermediate checkpoint with no pending interrupt or replay later writes from that point ([recovery limits](system-design.md#82-reload-and-crash-recovery)).
- The checkpoint saver's `exportSession` supplies content-free metadata by default and personal checkpoint content only with exact `personalContent: true`, which hosts must bind to an explicit user action. Host-local wires a metadata-summary download and a host-confirmed personal-content download; host-remote has no export UI. Export is lossy and supplies no import, sync, cross-device recovery or durable runtime-event history ([export semantics](../packages/storage-indexeddb/README.md#explicit-session-export), [scope](galaxie-project-brief.md#52-outside-the-mvp)).
- IndexedDB storage is not encrypted by the package and browser persistence is not permanence, so eviction can return a fresh start ([storage limits](../packages/storage-indexeddb/AGENTS.md#limits)).
- Ownership and logout need host composition, cannot fence a tab that bypasses ownership, and cannot undo an already-sent remote effect ([ownership](system-design.md#85-tab-ownership-and-takeover), [logout](system-design.md#86-logout)).

## Tools and MCP

- Third-party MCP servers and OAuth flows are unsupported; only host-controlled servers or gateways with configured principal credentials belong to this profile ([MCP scope](../packages/tools-mcp/README.md)).
- MCP resources, prompts, sampling, elicitation, roots, resumable streams and model-chosen tool wrappers are not exposed ([MCP profile](system-design.md#61-mcp-client), [client limits](../packages/tools-mcp/AGENTS.md#limits)).
- Runtime pin approval is not provided, and metadata pins detect changed definitions rather than changed behavior behind an unchanged definition ([pinning contract](../packages/tools-mcp/README.md)).
- Each principal uses one serial MCP client lane even when a binding permits greater concurrency, with a fresh listing before dispatch and no stream resumption ([client limits](../packages/tools-mcp/README.md)).
- Generic fetch, SQL and shell capabilities are not provided, and a write without the required host confirmation configuration fails `unsupported` ([broker flow](system-design.md#83-a-capability-call)).

## Security boundaries

- Trusted-first execution supplies no sandbox for arbitrary JavaScript, unreviewed agents or same-origin dependencies, which can bypass SDK-controlled paths ([trust boundary](security-review.md)).
- Data labels do not detect paraphrases sent to allowed destinations. Core rejects interaction URL candidates containing registered private strings in raw or twice percent-decoded form, with `+` treated as a space, unless `private-user` policy allows `third-party`. Parser-normalized candidates receive the same checks, including tab/newline/carriage-return stripping. When whole-URL decoding fails, each maximal run of valid percent escapes is decoded independently; invalid UTF-8 runs stay raw. The broker applies the same raw and twice-decoded matching to every argument string and key, including structured fields, only when private-user policy disallows the binding destination; allowed arguments are passed unchanged. Both guards retain the eight-character registration minimum and lowercase/whitespace normalization; they do not track taint or detect paraphrases, other encodings such as base64 or unregistered values. Unregistered path/query values and remaining structured channels still require host constraints ([residual channels](security-review.md#brief-97-b-and-c-duties)). Restore conservatively registers every saved submission string before exposing pending props, because historical submissions have no schema identity. Values present only in prior run input, capability output or checkpoint state cannot be reconstructed by that check; without a recovery store there are no saved submission strings to register.
- Manifests and digests do not provide signatures, publisher authentication or proof of safe behavior when both package and manifest can be replaced ([manifest trust model](system-design.md#62-generated-agent-manifests)).
- Client budgets and cooperative cancellation do not enforce provider billing or backend authorization ([baseline limits](security-review.md#adr-0012-baseline)).
- The output-safety hook covers routed reply text and tool-call arguments only, cannot retract already-allowed chunks, and does not cover direct models, capability results or every display callback ([output handling](security-review.md#owasp-top-10-for-llm-applications-2025)).
- Development warnings and lint rules are best-effort advice rather than runtime containment or exhaustive CSP/credential scans ([warnings](system-design.md#development-warnings), [lint limits](../packages/eslint-plugin/README.md)).

## Browser-built retrieval example

The [RAG example](../examples/rag-browser/README.md) offers LangGraph.js and optional LangGraph Python/pydantic-ai/DSPy builds. The pydantic-ai choice currently uses mock models and requires an answer-role provider declaring `tool-calling`. DSPy retrieves with program-owned arguments; with opt-in review it pauses before its first model call. It needs no tool calling, but its answer role needs a provider declaring `streaming`. Real-model ChatAdapter format reliability and its hands-on browser check remain unverified. Pending opt-in passage reviews restore on all four executors; default questions, answer displays and unsent review selections do not. Individual pasted-passage deletion and a prebuilt pinned-index format are absent. Python is omitted when the verified wheel cache is absent at build time. Its separate retrieval cache has no principal scoping, retention sweep or logout wipe. Concurrent builds can replace whole records; clear uses cross-tab invalidation and a durable content-free generation fence. Browser eviction loses the index. WebGPU is required for embeddings, with no WASM inference fallback. Full-corpus indexing, real-model retrieval/citation quality, reference-device performance and simultaneous embedding/chat GPU memory use remain unmeasured. The existing WebLLM context limit can reject large prompts. Python source is trusted and can reach Worker APIs through `js`; the lint aid and same-origin CSP do not make it an isolation boundary. Runtime assets and local build artifacts retain the page bundle's trust rather than an independent runtime SRI guarantee.

## Platforms and evidence

- Firefox, Safari, mobile devices, other GPUs and other OS/device combinations have no real-device evidence in the published matrix ([untested configurations](device-matrix.md#untested-or-unmeasured)).
- Real inference evidence is limited to the recorded Apple M5 Pro/Chrome 155 demonstrations, while automated Node and Chromium tests use fake models and engines ([device matrix](device-matrix.md)).
- Real worker-network capture, first downloads, latency distributions, main-thread long tasks, memory and the listed recovery/device measurements remain unmeasured ([MVP open items](mvp-exit-record.md#open-items-for-the-maintainers-decision)).
- The external developer trials and the pre-release legal review have no completed result in these records, and the maintainer's decision is pending ([MVP open items](mvp-exit-record.md#open-items-for-the-maintainers-decision)).
