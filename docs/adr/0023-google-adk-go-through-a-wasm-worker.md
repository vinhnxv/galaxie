# ADR-0023: Google ADK (Go) through a WebAssembly Worker, with policy kept in JavaScript

- **Status:** Proposed
- **Date:** 2026-11-04
- **Related:** brief §6.2, §7.4; ADR-0002, ADR-0012, ADR-0017, ADR-0018, ADR-0020, ADR-0022
- **Revisions:** 2026-11-04: created with stage AG1 (decision, pins, lock strategy, toolchain, first-run gate). Stages AG2 to AG5 turn the model and tool bridge, streaming, interactions and durable sessions on, each with its evidence. Stage AG6 records the agent-shape evidence and the limits in [the unsupported list](../unsupported.md#google-adk-go); the evidence below is now observed, not required.

## Context

Agent authors ask for Google's Agent Development Kit in Go (`google.golang.org/adk`). ADR-0020 covers the JavaScript adapter and ADR-0022 the Python one; both keep policy in JavaScript and let the framework run behind a bridge. Go has a first-party browser target: `GOOS=js GOARCH=wasm` compiles a program to one WebAssembly module and the toolchain ships `wasm_exec.js`, the glue that instantiates it.

A feasibility run on 2026-11-04 (a throwaway probe, not committed) found:

- ADK Go v1.9.0 (Apache-2.0, published 2026-10-15, `go 1.25.0` minimum) and `google.golang.org/genai` v1.57.0 compile for `js/wasm` with Go 1.27.3. The stripped module is about 30 MB (6.4 MB gzip, 4.5 MB brotli) and two builds are byte-identical with `-trimpath -ldflags="-s -w -buildid="`.
- `wasm_exec.js` needs only `'wasm-unsafe-eval'` to instantiate the module. Headless Chromium 156 ran a scripted ADK run in a module Worker under the unchanged strict mock CSP and Trusted Types with zero violations, and a control without `'wasm-unsafe-eval'` failed to compile.
- Go code reaches JavaScript through `syscall/js`. A `js.FuncOf` callback must not block, so goroutines await promises on channels; `main` must block with `select{}`; a cancelled context must unblock the awaiting goroutine itself.
- ADK Go has no integrity plugin, no registry-resolved model strings that avoid the public interfaces, and starts one goroutine per function call in a model turn.
- The ADK Go module graph pulls in gRPC, OpenTelemetry and Google client code that the wasm build links but a galaxie run never reaches; the Worker has no network path of its own.

## Decision

1. **A new package, not a fourth Pyodide framework.** `@galaxie/adapter-go` registers executor id `adk-go`. The dependency rules forbid adapters from importing each other, and the Go side needs a Worker, a bridge and a loader that share nothing with Pyodide. Core keys executors by id and needs no change.
2. **Pin ADK v1.9.0, genai v1.57.0 and the toolchain.** `go/go.mod` requires both modules and declares `toolchain go1.27.3`; `go/go.sum` pins every module hash and `go mod verify` runs in the checks. The newest ADK release at or before the fixed Go lock cutoff `2026-10-28T00:00:00Z` is v1.9.0.
3. **`go/wasm.lock` is the single record of the supply chain.** It lists the toolchain, the build flags, every module compiled into the wasm build with its version, license and checksum database record number, the cutoff, and the SHA-256 and size of `wasm_exec.js`. The release-age rule is checked against the order in which versions first reached the public checksum database, not the commit time, because a tag can be backdated: every locked module's record number must be below the record number of the first version the public module index lists at the cutoff. The lock is regenerated by `scripts/check-go-lock.ts --update`, the only script that uses the network for it. A lock test compares the lock with `go list -deps` of the wasm packages and with `go.sum`.
4. **The wasm is the author's build artifact, verified before it is compiled.** Authors build with `GOOS=js GOARCH=wasm CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -buildid="`. The host passes the wasm URL, length and SHA-256; the Worker loader fetches same-origin bytes, checks both with WebCrypto and only then calls `WebAssembly.compile`, failing `unavailable` with a fixed message on any mismatch. `wasm_exec.js` is copied from `$(go env GOROOT)/lib/wasm/` after its digest matches the lock; hosts bundle it with the Worker and it is not committed. Neither check is a run-time proof of safe behavior: they bind the bytes the host reviewed to the bytes the Worker runs.
5. **Policy stays in JavaScript; Go is trusted.** Routing, consent, labels, budgets, credentials, output checks and authorization stay in the page, as in ADR-0018. Go code is author code and can call anything `syscall/js` reaches in the Worker. The loader installs throwing stubs for `fetch`, `WebSocket`, `EventSource`, `XMLHttpRequest`, `Worker` and `SharedWorker` before the module starts, so ordinary Go networking (`net/http`) fails closed and counts the attempt; the CSP `connect-src` is the boundary underneath. The stubs are a guard against accidents, not an isolation boundary.
6. **Go standard output is discarded and observability stays off.** The module set carries the OpenTelemetry API only, so ADK spans are no-ops, and the Worker replaces the glue's `fs.writeSync` and `write`.
7. **Executor features turn on only with their evidence.** The adapter first registers `adk-go` with every feature false and a run failing `unsupported` when its event stream is first read. Later stages add the model and tool bridge, streaming, interactions, durable sessions and agent shapes, each turning its flag on in the same change that adds its evidence, as in ADR-0022. No stage changes the goldens or matrices of another executor.
8. **No CSP, Trusted Types or ADR-0012 relaxation.** The module Worker is loaded the same way as the other Workers, and `'wasm-unsafe-eval'` is already in the strict policy.

**Amendment (2026-11-07):** [Proposed ADR-0026](0026-adapter-kit-package.md) amends decision 1's premise that the Go Worker, bridge and loader share nothing with Pyodide: pure common adapter and bridge helpers may move to the non-adapter `@galaxie/adapter-kit` package. The separate Go adapter decision stands; its loader, WASM glue and framework-specific behavior stay local. Adapter-to-adapter imports remain forbidden, and today's dependency rules stay in force until the extraction lands.

## Alternatives considered

- **TinyGo.** Rejected: ADK Go and genai use reflection, generics and standard library packages TinyGo does not support, and the upstream test suite targets the standard toolchain.
- **`wasip1` instead of `js`.** Rejected: it needs a WASI shim, offers no promise bridge and gives up `syscall/js`, which the bridge relies on.
- **A prebuilt galaxie-hosted agent binary.** Rejected: the agent code is the author's, so the author builds; the host verifies the digest.
- **Running ADK Go behind a server.** Out of scope: galaxie runs agents in the browser with no agent backend.
- **A syntax-level Go source lint aid.** Not built in this decision; the registry validation of a later stage and the CSP already refuse every route it would flag.

## Consequences

- The Worker download is the 27 to 30 MB module (about 5 to 6 MB compressed) plus the 17 kB glue file. Hosts should serve it with compression and a long cache lifetime.
- Cold start is dominated by compiling the module; stage AG1 records the number on the maintainer's machine as a measurement, not a guarantee.
- Authors need Go 1.27.3 (or the pinned toolchain) to build their agent. CI installs it with a commit-pinned action; tests skip with a fixed message when `go` is absent.
- The wasm build links gRPC and Google client packages that a run never reaches. They are in the lock so the module list is complete, and a run cannot use them for network access through the Worker stubs and the CSP.

## Verification

Observed in stage AG1 (scripted models only, no real model download):

- Lock and toolchain: the lock covers exactly the modules the wasm build compiles, every module's license is an allowed permissive license and its checksum database record precedes the cutoff, `go.sum` has both hashes of each module, the glue digest matches and a one-byte change fails, and two builds are byte-identical (`tests/conformance/go-lock.node.test.ts`).
- Loader and adapter: a tampered byte, a wrong length, a wrong digest and a disagreeing declared length fail before compile, and the egress stubs replace the network surfaces before the module starts (`packages/adapter-go/test/loader.node.test.ts`, with a fake scope); a module that never signals ready times out and its Worker is terminated (`packages/adapter-go/test/adapter.node.test.ts`). A real `net/http` call is refused and counted only in the gate, in the Node and Chromium lanes; no tampered module is run in a real browser.
- Gate: a scripted ADK run (text, a function tool through a JavaScript capability, a confirmation pause and resume, a long-running tool, SSE partials, sequential, parallel and loop agents, an output schema, transfer, a raising tool, a raising model, a cancelled context and an event-replay restore) passes natively, on Node and in headless Chromium under the unchanged strict CSP and Trusted Types with no violation and no non-origin request (`go/gate/gate_test.go`, `examples/rag-browser/test/go-gate.node.test.ts`). The lock digests the glue source file as copied; a bundler may rewrite it, so the shipped bytes are not hash-checked. Measured on the maintainer's Apple M5 Pro with headless Chromium 156 and Go 1.27.3 (scripted models, a local preview server, one run each, so demonstrations rather than benchmarks): the stripped module is 29,960,388 bytes (6,504,949 gzip at level 9, 5,290,746 brotli at quality 9) and two builds are byte-identical. Through the shipped Worker, fetch plus digest check took 42 ms, compile 9 ms and runtime start 35 ms, and the adapter reported ready after 86 ms; the same loader on Node took 38, 14 and 39 ms. Both are far inside the 48 MB and 10 s stop thresholds. Compile is short because Chromium compiles lazily on first call, so the first scripted run pays part of that cost; real-device cold start, memory and first-token latency stay unmeasured. The gate also records that a tool error does not end an ADK Go run: the error becomes the function response and the model continues, while a model error and a cancelled context end the run.

Observed in stages AG2 to AG6 (scripted models only, no real model download; every figure is from the maintainer's machine, one run each, and is a demonstration rather than a benchmark):

- Model, tools and run: the model forwards each request to the JavaScript router, a function tool calls a host capability through the broker, and a denied or failing capability, a raising model, the step budget, a blocked argument, abort, a panic, `os.Exit` and a loop that ignores its context end as documented (`tests/conformance/adk-go.node.test.ts`, `tests/conformance/adk-go-run.node.test.ts`). The native Go recorder, the Node Worker and headless Chromium under the unchanged strict CSP and Trusted Types produce the same wire transcript for every case in `tests/conformance/cases-adk-go`, against goldens recorded from Google's own runner (`go/conformance/conformance_test.go`, `examples/rag-browser/test/adk-go-reference.node.test.ts`). A scan of bridge traffic, events, snapshots and spans finds no per-call credential (`tests/conformance/adk-go-scan.node.test.ts`).
- Streaming: every growing reply passes the output-safety hook before it is forwarded, a block fails `denied` and nothing unchecked reaches Go (`packages/adapter-go/test/stream.test.ts`, the `stream-*` cases).
- Interactions: a confirmation and a long-running tool end the run with one host-rendered interaction and the answer continues the session; the pause rule refuses every place where ADK's resume would skip a sibling (`go/galaxie/trees_test.go`, `go/galaxie/pause_sites_test.go`, `packages/adapter-go/test/interaction.node.test.ts`, the `confirm-*` and `long-running` cases).
- Durable sessions: the program returns a closed-shape record that the page stores through the byte-record port and sends back; a reload with a new Worker at every pause reproduces the golden for each pausing case in Node and Chromium, and tampering without the key, with the key, or with the digest fails before any capability runs (`tests/conformance/adk-go-restore.node.test.ts`, `packages/adapter-go/test/persist.node.test.ts`, `go/galaxie/record_test.go`).
- Agent shapes: Sequential, Parallel, Loop (bounded and with an exit tool), transfer between an `LlmAgent` and a sub-agent, and a confirmation in a transfer target or in the last child of a sequence all reproduce their goldens in the three lanes. The Parallel case compares its wire lists by canonical text because the branches reach the page in any order. Parallel write branches keep branch-local effect scopes whichever branch reaches the broker first, and a restore after the pause that follows a Parallel stage runs no branch write again (`tests/conformance/adk-go-agents.node.test.ts`). `agenttool`, an agent or tool built directly with ADK and a toolset fail `unsupported` before anything runs (`go/galaxie/shapes_test.go`). `subgraphs` stays false.
- Size and cold start, final reference module of stage AG6: 30,109,586 bytes stripped; Go ready after 94 ms on Node and 95 ms in headless Chromium (stage AG5: 30,070,117 bytes, 95 ms; stage AG1: 29,960,388 bytes, 86 ms). Both stay far inside the 48 MB and 10 s stop thresholds.

Still open, so the status stays Proposed: a real-device measurement of boot, memory and first-token cost; a real-model run; the external developer trial; the integrity limits and carried-forward findings listed in [the unsupported list](../unsupported.md#google-adk-go).
