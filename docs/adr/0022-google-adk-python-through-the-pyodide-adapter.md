# ADR-0022: Google ADK (Python) through the Pyodide adapter, with an explicit wheel list

- **Status:** Proposed
- **Date:** 2026-11-03
- **Related:** brief §6.2, §7.4; ADR-0002, ADR-0012, ADR-0017, ADR-0018, ADR-0020, ADR-0023 (the Go sibling)
- **Revisions:** 2026-11-03: created with stage AP1 (pin, closure, lock strategy, first-run gate); stage AP2 adds the model, tool and run evidence (features stay false); stage AP3 adds streaming and turns `streaming` on; stage AP4 adds interactions and turns `interrupts` and `resume` on; stage AP5 adds durable sessions and turns `checkpoints` on; stage AP6 adds the agent-shape cases, the parallel-write replay test, a credential scan and the documentation, and leaves the status Proposed.
  2026-11-10: replaced cryptography 47.0.0 with a vendored 50.0.2 WASM build linked to OpenSSL 4.0.3; aligned the Worker with the native pin without changing the maintained cutoff or other framework wheel sets.
  2026-11-10: recorded the workflow-agent pause spike below; enabled evidenced Sequential and single-branch Parallel pauses with ADK resumability, retained the Loop refusal, and added workflow-state checks on restore.

## Context

Agent authors ask for Google's Agent Development Kit in Python. ADR-0018 gives Python a boundary: a dedicated Pyodide Worker, proxies only in the `galaxie` Python package, and policy kept in JavaScript. ADR-0020 covers the JavaScript ADK adapter. Its Python sibling needs the same executor shape as pydantic-ai and DSPy, but the engine is heavier and has hazards of its own. A feasibility run on 2026-11-03 put `google-adk` 2.12.0 in Pyodide 314.0.7 on Node and found four:

- The first `Runner.run_async` imports `fastapi`, `authlib` (and so `cryptography`) and `opentelemetry` lazily. An import-only probe passes while the first run fails.
- ADK's metadata would move three existing pins: `opentelemetry-api`, `tenacity` and `websockets`, and `opentelemetry-sdk` places an exact pin on `opentelemetry-semantic-conventions`.
- A string model name resolves through ADK's registry to `Gemini` and the Google client, a route around galaxie.
- Nothing had run in Chromium under the strict CSP or through the galaxie bridge.

## Decision

1. **A fourth framework option, not a new package.** `createPyodideAdapter({ framework: 'adk' })` gives executor id `adk-python`, beside `langgraph-python`, `pydantic-ai-python` and `dspy-python`. Core keys executors by id and needs no change. Registration is a `PythonFramework` member, the id string, the wheel tag `adk`, a driver module, a boot import probe and, from stage AP2, a `galaxie.adk` Python module.
2. **Pin `google-adk` 2.12.0.** It is the newest release at or before the fixed Python lock cutoff `2026-10-23T17:00:00Z` (uploaded 2026-10-13, Apache-2.0, `requires-python >=3.11`). Its 2.x line is unrelated to the JavaScript package's 2.3.0. 2.13.0 (uploaded 86 minutes after the cutoff) waits for the next cutoff. A bump re-runs the hidden-import discovery, the symbol-presence test and the conformance lane.
3. **Keep framework pins aligned; the Worker gets an explicit wheel list.** At AP1, `python/galaxie/pyproject.toml` gained an `adk` extra, `["google-adk==2.12.0"]`. `python/pyproject.toml` gained `override-dependencies` (`opentelemetry-api==1.45.1`, `opentelemetry-semantic-conventions==0.66b1`, `tenacity==9.2.1`, `websockets==17.3`) and extra constraints (`cryptography==47.0.0`, `cffi==2.0.0`, `pycparser==3.0`), so `uv lock` added 22 packages and moved none. `requirements.lock` gained ten wheels tagged `adk` and the `adk` tag on 19 shared wheels. The `adk` set is 29 wheels and 12,622,878 bytes. Hashes come from PyPI and the Pyodide lock and are checked by `fetchWheel`. The Worker installs with `depends: []`; `micropip.install` is never used for ADK. `watchdog`, `uvicorn`, `grpcio`, `aiosqlite`, `graphviz`, `click`, `python-dotenv`, `python-multipart`, `opentelemetry-sdk`, `pyasn1*`, `mcp` and `google-cloud-*` stay out of `requirements.lock`; the tests assert it. Maintenance on 2026-11-10 moves the native release cutoff to `2026-11-03T00:00:00Z`, still at least seven days old, pins native cryptography 50.0.2 and pyasn1 0.6.5, omits DSPy's unused diskcache backend, and aligns msgpack 1.2.4 using its published CPython 3.14 WASM wheel. The LangGraph wheel bytes and fingerprint change accordingly. The cryptography patch replaces the affected Pyodide 47.0.0 wheel with a [vendored 50.0.2 WASM build](../../python/wheels/README.md) linked to OpenSSL 4.0.3, bringing the 29-wheel ADK set to 12,818,857 bytes. Pyodide 314.0.7 publishes no compatible patched cryptography wheel, so this repository maintains the replacement build and its provenance. `fetchWheel` verifies its length and hash like every other locked wheel. The offline gate checks the loaded extension and constrained-CA wildcard refusal on CPython, Node Pyodide and Chromium Pyodide. Every shared distribution must have one version, and framework conformance remains required.
4. **The gate proves the first run, not the import.** The gate is a scripted `Runner.run_async` (text, tools, confirmation, long-running tools, SSE streaming, sequential, parallel and loop agents, structured output, transfer, failures, cancellation, event-replay restore and the integrity plugin) on CPython, on Pyodide in Node, and on Pyodide in headless Chromium under the unchanged strict CSP and Trusted Types with `fetch`, `WebSocket` and `XMLHttpRequest` replaced by throwing stubs. It also asserts that no thread starts during the run (a spy on `threading.Thread.start`; on Pyodide threads cannot start at all, so the assertion is meaningful on CPython) and that the modules kept out of the Worker (`uvicorn`, `watchdog`, `grpc`, `aiosqlite`, `mcp`, `opentelemetry.sdk`) are absent. The Worker boot imports the hidden modules (`fastapi.openapi.models`, `authlib.integrations.requests_client`, `opentelemetry._logs`, `opentelemetry.semconv`) so that a missing wheel fails at boot with the fixed `unavailable` error, not at the first run. Every bump repeats the discovery by removing each candidate from a working environment.
5. **Fail-closed tree validation by registry membership** (applies from stage AP2). Host helpers record every model and tool they create in a module-private registry. At prepare the driver accepts exact classes `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent`, only registry models and tools (resolving inherited and omitted models the way ADK does), and refuses `Workflow`, `AgentTool`, toolsets, code executors, planners, plugins, `App`, string model names and `Gemini` with fixed `unsupported` errors. Authors never see the Runner.
6. **The adapter owns the Runner and every service** (stage AP2). It builds the `App` with one plugin, ADK's `ToolCallIntegrityPlugin`, a galaxie session service and a `RunConfig`, and drives only `run_async`. Fatal errors propagate out of `run_async` in 2.12.0; a per-run failure slot covers author callbacks that swallow them. `limits.steps` is enforced once, in the model's call count.
7. **Pauses end the run; resume is a new `run_async`** (stage AP4, decision 11), as in ADR-0020. Sessions persist as an event log through the existing byte-record port with a per-session integrity key kept in record metadata (stage AP5); the record must fit the 1 MiB bridge frame.
8. **Executor features turn on only with their evidence.** The adapter first registered `adk-python` with `streaming`, `interrupts`, `resume`, `checkpoints` and `subgraphs` all false. Stage AP2 runs text and tool-calling agents end to end with those flags still false; stage AP3 turns `streaming` on; stage AP4 turns `interrupts` and `resume` on; stage AP5 turns `checkpoints` on. Each flag turns on only with the evidence listed under Verification. `subgraphs` stays false for the reasons ADR-0020 and ADR-0018 give.
9. **Python is trusted.** A Worker can `import js`; the tree validation and the lint aid reduce accidents and are not an isolation boundary (ADR-0018). Only third-party wheels have independent hash checks. No CSP, Trusted Types or ADR-0012 guarantee changes.
10. **Streaming projects ADK's SSE events onto the existing stream modes** (stage AP3). A run always asks ADK for SSE, so every model call is a streamed bridge request and the routed provider must declare `streaming`. The runtime checks each growing chunk and the final reply before Python receives them; the router-backed model turns the checked chunks into partial responses and the final reply into the complete response. `messages` events carry `{ author, text }` deltas of at most 4096 code points: a surrogate pair split across two provider chunks is joined first and never split, and thought parts and tool-call fragments are excluded. `updates` events carry only `{ step, tool, index }` markers (the offered tool's name and a run-wide position), never a call ID, an argument or a result. A mid-stream block fails `denied` without forwarding the blocked delta; earlier deltas are not retracted. The stream is not journaled.
11. **Interactions map ADK's two pause kinds onto one galaxie interaction** (stage AP4). `capability_tool(..., require_confirmation=True)` uses ADK's confirmation (experimental in 2.12.0): ADK emits an `adk_request_confirmation` call and the invocation ends. `capability_tool(..., long_running=True)` runs the capability at call time and the result is ADK's pending response; the executor stops the run at the next event, before ADK asks the model about it. Both end the run, `Executor.run` returns no output, the adapter reads `pending` from the executor and publishes the interaction, and the answer is a new `run_async` carrying `FunctionResponse` parts that use ADK's own call IDs. Those IDs never reach author code, the UI, markers or galaxie's own records; since stage AP5 they appear only inside the stored ADK event log and pending request, which stay on the device. The author's `interaction(requests)` hook returns one four-field request (`surfaceId`, `viewRevision`, `component`, `props`) from positional requests `{ kind: 'confirmation' | 'long-running', tool, args }`; an optional `resume(requests, action, payload)` hook returns one decision per request (`{ confirmed }` or `{ response }`). Without it the default resume accepts `approve` or `deny` with payload `{ indexes }` that covers every request exactly once and refuses long-running requests, which need the author's hook. The interaction ID is the SHA-256 of the conversation ID, the pause ordinal and the request content (tool, kind and arguments), so scripted call IDs that repeat still give distinct interactions and a changed request gives a different ID. The adapter compares the submitted ID with the pending one and fails `stale` before the Worker runs; the executor repeats the check and validates the action and payload before building any ADK message, so a stale, unknown or malformed answer runs no tool. A failed resume rolls the session back to the pause and keeps it pending; a retry runs the approved tool's capability again, so a write needs the host's recovery store (without it host writes repeat, as for every executor). Cancelling or aborting a run ends the Worker, which drops the in-memory pause: the session is then lost and a later answer fails `unavailable`. A new prompt while a pause is pending fails `invalid`. Stage AP5 makes the pause durable (decision 13). The stream carries a content-free `paused` marker (`{ step, tool, index }`) per request.
12. **Pause shapes require evidence.** A uniquely named leaf can pause for confirmation or a long-running result under `SequentialAgent` ancestors, including a first or middle child and nested sequences. A single pausing agent beneath each `ParallelAgent` may ask for confirmation, including when later sequence stages follow the fan-out. Newly enabled positions use ADK's resumable invocations; trees the original last-child rule accepted keep the non-resumable runner. Pauses under a `LoopAgent` remain refused: native resumability continues a bare worker but repeats an earlier sibling's finished tool in a writer/checker loop. Multiple pausing agents under one `ParallelAgent`, long-running tools under a `ParallelAgent`, pausing agents with sub-agents or an `LlmAgent` ancestor, and unknown or duplicate pausing names fail `unsupported` at prepare. Resumable apps additionally refuse any duplicate agent name, any `temp:` output key and any `LlmAgent` with transfer children. The spike below records the mechanism and evidence; `test_adk_python_refused_shapes.py` preserves the original non-resumable results. A pausing tool without an `interaction` hook fails `unsupported` at prepare. A confirmation beside a long-running call in one model turn fails `unsupported` before any tool runs; a confirmation beside an ordinary call and a long-running call beside an ordinary call are supported. Resume must answer every pending request at once or fails `invalid`. `subgraphs` stays false.
13. **Sessions are durable through the byte-record port** (stage AP5). With `checkpoints` on, each galaxie session maps to one random conversation ID, and after every successful run the executor writes one checkpoint revision (20-digit zero-padded IDs, an `__interrupt__` write that is cleared on completion, the checkpoint as commit marker). The checkpoint (`adk-python.session/v1`) holds the ADK event log (final events only; partial events and binary parts are never stored). The metadata (`galaxie.adk-python-state/v1`) holds a random 32-byte session key, the pause count and the pending interaction with its requests. Restore replays the log into a fresh ADK session and runs ADK's own `ToolCallIntegrityPlugin` stamp check with the stored key before any run or pending read; a changed pending call, a spliced event log, an event carrying ADK's internal restored-event marker (which would make ADK skip its stamp check), a forged interaction ID or an unreadable record fails `unrecoverable` with the executor left unchanged and other sessions readable. The key sits beside the record, so it detects edits by a writer who cannot change both and gives no secrecy against one who can; ADK's plugin protects function-call arguments and stamps, not event deletion or IDs, so the executor also checks the pending asks against the log. Restored text is registered private through `registerRestoredData` before any live call or interaction validation, and a restored pause is republished from the stored request without calling the author's `interaction()` hook again. The stable effect scope `adk-python/{conversation}/{branch}/{ordinal}/{position}` lets the recovery store replay a write receipt after a crash instead of running the write twice. A bridge frame is capped at 1 MiB, so the record limit is about 719 KB of raw bytes: `append_event` tracks the projected record size and fails the run `unsupported` before the next model or tool dispatch when a non-final event would leave less than 16 KiB for the final reply, and a start whose stored record is already within that margin is refused. A long-running pause event, which ADK treats as final, leaves the same margin, and a pending request above 16 KiB is refused before it is published so that a restore reply, which echoes it in two interrupt writes, stays inside one frame. A failed or cancelled run writes nothing. `subgraphs` stays false.

14. **Agent shapes are supported by evidence, not by class name** (stage AP6 and the workflow-agent pause spike). A tree of `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent`, and an `LlmAgent` with `sub_agents` that transfers with `transfer_to_agent`, runs, streams and returns the same output as native ADK 2.12.0 (cases `agents-sequential`, `stream-agents-sequential`, `agents-parallel`, `agents-loop`, `agents-transfer`). Pauses follow decision 12, with live and reload parity cases listed below; `agents-confirm-last` keeps its original non-resumable behavior. `Workflow`, `AgentTool` and the refused pause shapes fail `unsupported` at prepare. Parallel writes keep the unchanged branch-local scope `adk-python/{conversation}/{branch}/{ordinal}/{position}`. Recovery tests cover reversed branch arrival, a reload while paused and a failed resume after an approved write: each logical write reaches the host once through its succeeded receipt. Without the host recovery store, writes can repeat. `subgraphs` stays false: ADK sub-agent events carry `author` and `branch`, not LangGraph namespaces, so galaxie exposes no nested stream paths or checkpoint namespaces for sub-agents. `AgentTool` would need an adapter-owned wrapper with its own run configuration, integrity plugin and session keying.

## Alternatives considered

- **A new package for ADK Python.** Rejected: it needs the same Worker, bridge, wheel verification and checkpoint op as the adapter, so it would duplicate them.
- **`micropip` with a resolver.** Rejected: the Worker restores the real `fetch` after install, a resolver makes the closure unpinned, and ADR-0018 decision 10 requires exact hash-pinned wheels.
- **Metadata-only stand-ins for `authlib` and `fastapi.openapi.models`.** Not built: they would drop about 2.5 MB, but untested stand-ins raise drift risk against ADK. A measured Worker boot cost on a real device would reopen the call.
- **A separate uv project for the ADK lane.** The fallback if the overrides are judged too invasive; the Worker set would be the same.
- **Stand-ins for `watchdog` and `uvicorn`.** Not built: no resolver runs in the Worker, and the CPython reference environment installs them normally.

## Consequences

- The Worker download for an ADK agent is the 29-wheel set (12,818,857 bytes after the cryptography patch). The rag-browser build emits those wheels because its asset plugin emits every locked wheel. The vendored cryptography build and its linked OpenSSL require maintained provenance, license texts and repeated runtime checks when rebuilt.
- Licenses of the ten new wheels, from their dist-info metadata: `google-adk` Apache-2.0; `google-genai` Apache-2.0; `google-auth` Apache-2.0; `opentelemetry-semantic-conventions` Apache-2.0; `cryptography` Apache-2.0 OR BSD-3-Clause; `authlib` BSD-3-Clause; `joserfc` BSD-3-Clause; `starlette` BSD-3-Clause; `fastapi` MIT; `annotated-doc` MIT.
- `google.genai` imports `ssl`; the gate runs on Pyodide in Node and Chromium, so the import resolves there. A local CPython needs an OpenSSL-linked build.
- `opentelemetry-sdk` is absent from the Worker, so ADK spans are no-ops through the API. Galaxie's own allowlisted spans cover runs. The CPython reference environment still installs `opentelemetry-sdk` 1.42.1, whose exact pins disagree with the forced `opentelemetry-api` and semantic-conventions overrides, so the CPython gate runs a forced combination that the Worker does not have.
- ADK's `Sequential`, `Parallel` and `Loop` agents emit `DeprecationWarning` in 2.12.0 and work. Confirmation, agent state and `ResumabilityConfig` are experimental. Temporary state is lost on resume; resumable apps refuse `temp:` output keys. A version bump re-runs the workflow pause cases.

## Verification

### Workflow-agent pause spike (2026-11)

The native evidence uses ADK 2.12.0's own Runner and scripted models in
`tests/conformance/cases-adk-python/test_adk_python_resumable_shapes.py`.
`test_resumable_shape_matches_uninterrupted_dispatches_and_tools` compares model
dispatches, final texts and tool execution counts with the same uninterrupted
script. The parameter names below identify each shape.

| Shape | Native resumable result | Galaxie evidence | Decision |
| --- | --- | --- | --- |
| First Sequential child | `first`: paused leaf finishes, then its successor runs once | `agents-confirm-first`, live and reload | Accept |
| Middle Sequential child, including an earlier writer | `middle`, `sequence-writer`: earlier work runs once, later child runs after approval | `agents-confirm-middle`; agents-lane sequence receipt tests | Accept |
| Nested Sequential child with successors | `nested`: inner and outer successors each run once | `agents-confirm-nested`, live and reload | Accept |
| Long-running middle child | `long-running`: answer continues the leaf and its successor | `agents-long-running-middle`, live and reload | Accept |
| One confirming Parallel branch followed by a merger | `parallel`: the finished writing sibling is not repeated | `agents-confirm-parallel`, `agents-confirm-parallel-reversed`, both reloaded; agents-lane write tests in both orders | Accept |
| Loop worker | `loop` continues twice, but `test_loop_with_writer_repeats_a_finished_tool_and_stays_refused` records writer inputs `[10, 10, 20]` for two logical writes, with no extra model calls | Python and Worker prepare refusals for Loop pauses | Refuse the general Loop pause shape |
| Two confirming Parallel branches | `test_two_parallel_confirmations_are_native_but_remain_refused_by_the_single_pause_tracker`: both ask, only the left branch resumes | Python and Worker prepare refusals | Refuse |

Only the newly enabled positions set `ResumabilityConfig(is_resumable=True)` on
the adapter-owned `App`. ADK stores workflow progress and finished branches in
the event log, then resumes the paused invocation. Existing accepted trees keep
the original runner and golden bytes. ADK documents tool resumption as
at-least-once; the host recovery journal replays succeeded receipts using the
unchanged effect scopes. The agents lane (`tests/conformance/adk-python-agents.node.test.ts`)
counts actual host invocations across reloads and both Parallel arrival orders.
After a model fails following an approved write, the pending checkpoint stays
unchanged and core retries the durable accepted answer on restore; the write
still reaches the host once, without another submission.

The tracker holds one pending interaction. More than one pausing agent beneath
any Parallel ancestor is refused, and long-running tools beneath a Parallel
ancestor are refused because interleaved sibling calls can reset the tracker's
single long-running call list. Pausing transfer targets and pausing agents with
children remain unproven. Because resumability applies to the whole app, duplicate
names anywhere in that app are refused: ADK keys progress by name. `temp:` output
keys are refused because ADK drops temporary state on resume, and `LlmAgent`
transfer children are refused because their resumable routing was not exercised.

Restore checks state authors and direct-child names, loop counter types and
bounds, forward child/iteration progress, the current child on the pending
agent's ancestry, and completion markers for observed Parallel siblings. A
non-resumable record cannot carry agent state. Resumable workflow records must
have empty `node_info`; output routing fields are always refused. ADK's standalone
LlmAgent runner writes legacy records with exact static ancestry paths using `@1`
per agent, such as `router@1/specialist@1`. Only that known author/path pair or an empty path
is accepted for a non-resumable LlmAgent-root tree. Changed paths, including a
different ordinal, fail `unrecoverable` before installation or dispatch. Python
tests in `python/galaxie/tests/test_adk.py` cover these checks, legacy transfer
round trips and failed-resume scope stability. A writer who can forge a fully
consistent record and its colocated key remains outside these integrity checks.

The six new goldens reproduce in the Node Pyodide live and reload lanes
(`tests/conformance/adk-python.node.test.ts` and `adk-python-restore.node.test.ts`).
The existing Chromium subset and credential-scan lane remain regression gates;
the new workflow-pause cases have no dedicated Chromium evidence. No real model
or device measurement is added. The non-resumable evidence file remains unchanged.

Extension decision: `adk-js` 2.3.0 exposes `resumabilityConfig` and is a candidate
for a separate follow-up with its own evidence. `adk-go` v1.9.0 has no resumable
invocation and stays refused; `go/galaxie/trees_test.go` records the lost successors
and iterations. A Go extension would need a separate continuation or replay design.
Neither executor changes in this spike. ADK's deprecated workflow agents and
experimental resumability require these cases to be rerun on any version bump.

### Earlier evidence

Observed in stage AP1 (scripted models only, no real model download):

- CPython: the offline scripted gate passes against a lock-synced environment (`python/galaxie/tests/test_adk_gate.py`).
- Pyodide on Node: the same gate passes with the 29 wheels installed through `loadPackage` with integrity checks, no network fetch and no thread (`packages/adapter-pyodide/test/adk-gate.node.test.ts`).
- Headless Chromium: the same gate passes under the unchanged strict CSP and Trusted Types with no violation, no external request and no network attempt (`examples/rag-browser/test/adk-gate.node.test.ts`).
- Lock: no pin moved and the three existing wheel sets and fingerprints are unchanged (`tests/conformance/python-wheels.node.test.ts`).
- Adapter: the boot import probe resolves every hidden module in the Worker, and a withheld wheel fails the boot with `unavailable` at prepare (`packages/adapter-pyodide/test/adapter.node.test.ts`).

Observed in stage AP6 (scripted models only, no real model download):

- Shapes: six more native CPython transcripts (`agents-sequential`, `stream-agents-sequential`, `agents-parallel`, `agents-loop`, `agents-transfer`, `agents-confirm-last`) reproduce on Pyodide in Node, and `agents-sequential` and `agents-confirm-last` in real headless Chromium under the unchanged strict CSP; `agents-confirm-last` also reproduces across fresh Workers over one store, in Node and across Chromium page reloads (`tests/conformance/adk-python.node.test.ts`, `adk-python-restore.node.test.ts`, `examples/rag-browser/test/adk-python-conformance.node.test.ts`). The lanes script each model by agent name (the name in ADK's system instruction) and compare the requests each agent saw; `agents-parallel` sorts concurrent requests by agent and turn and orders its two branches with a reply gate in both lanes. The matrix lists every case, records the shape boundaries and keeps `differences` empty.
- Native non-resumable results (`tests/conformance/cases-adk-python/test_adk_python_refused_shapes.py`, run by CPython only): a pausing last child of a `SequentialAgent` resumes and finishes; a pausing first child never runs its successors; a pausing `LoopAgent` worker never starts the next iteration; a pausing `ParallelAgent` branch resumes alone and the agent after the fan-out never runs; a transfer target resumes in place; `AgentTool` and `Workflow` run natively. These results explained the stage AP6 prepare refusals. The workflow-agent pause spike above supersedes the Sequential and single-branch Parallel refusals; the Worker prepare test still supplies the interaction hook to isolate the shape rule.
- Parallel writes (`tests/conformance/adk-python-agents.node.test.ts`): two branches each call a write capability; the first run writes both and then fails; the same prompt on the same session re-dispatches the branches with the arrival order reversed, no capability runs again and the journal still holds two succeeded records. The test counts capability invocations, so a replay that ran a write again would fail it.
- Credential scan (`tests/conformance/adk-python-scan.node.test.ts`): a generated credential supplied per call to an OpenAI-compatible provider over an injected fetch appears only in the request's authorization header, through success, a 401 and a transport failure. It is absent from everything the Worker sends or receives (with base64 fields decoded), run events, snapshots, diagnostics, development warnings, spans, stored checkpoint rows and the recovery journal; the prompt and reply markers are also absent from spans, diagnostics and warnings. Positive controls show the scanner sees non-enumerable errors, bytes and encoded fields. Console and warning silence is covered by `adk-python-run.node.test.ts`.
- Limits: the scans run with scripted models and an injected fetch; no real model, no device measurement of boot, memory or latency, and no third-party endpoint exists. The integrity key and the log share one store (stage AP5). Parallel branches rely on ADK 2.12.0's branch naming; a bump re-runs the shape cases.

Observed in stage AP5 (scripted models only, no real model download):

- Python unit tests (`python/galaxie/tests/test_adk.py`): the record round trip; a pause restored without asking the author's hook again; the interaction ID covering request content; the key absent from the checkpoint; tamper refusal for the event log and the metadata (stamped call arguments, a confirmation's original call, names, cleared stamps, a missing confirmation event, duplicated or partial events, extra schema fields); records spliced from another session; a failed restore leaving the executor unchanged; a failed run writing nothing; frame-limit failures before the next dispatch, the start margin and the largest permitted record round-tripping; binary parts never stored.
- Worker lane on Node (`tests/conformance/adk-python-restore.node.test.ts`): six pause goldens (`confirm-approve`, `confirm-deny`, `confirm-two`, `long-running`, `confirm-consecutive`, `stream-confirm-approve`) reproduce across fresh Workers over one store with the same pending interaction republished at each restore; an answer accepted before the reload is reconciled; an approved write executed before a lost Worker replays its receipt and never runs twice (`approved-write`, `resumed-write`), and a changed replayed write fails `unrecoverable` without invoking the capability; a record by another executor is refused before any checkpoint read; stored-key, call-argument, pending-request and interaction-ID tampering fails `unrecoverable`; a corrupt snapshot leaves another session restorable; a completed run replaces an orphan interrupt marker.
- Chromium (`examples/rag-browser/test/adk-python-conformance.node.test.ts`): `confirm-approve` and `confirm-consecutive` restore across page reloads with reopened IndexedDB and match their goldens, and `approved-write` replays its receipt, all under the unchanged strict CSP with no violation and no external request.
- Limits: the integrity key and the log share one store, so a writer of both can forge a session; recovery data must stay on-device under the checkpointer's app and principal scope; no real model, credential scan or device measurement exists. The `checkpoints` flag turns on and the matrix matches the adapter; `subgraphs` stays false.

Observed in stage AP4 (scripted models only, no real model download):

- Interactions: a confirmation pauses with one interaction and runs no tool before the answer; approve runs the tool once, deny returns a fixed rejection to the model; two confirmations in one model turn form one interaction that the default resume covers once each; a long-running tool's capability runs at call time and the author's resume supplies the real result; scripted call IDs that repeat still give distinct interaction IDs (`python/galaxie/tests/test_adk.py`).
- Failures before any tool runs: an unknown, other-session or already-answered interaction ID fails `stale`; a payload that misses, repeats or adds an index, an action other than approve or deny, a malformed resume object and an author resume whose answers do not match fail `invalid`; a failed resume keeps the pause answerable; a new prompt while a pause is pending fails `invalid`.
- Native references: each refusal rule in decision 12 comes from a result observed on native ADK 2.12.0 in throwaway probes before the rule was written (not committed, so the rules themselves are covered by the Python unit tests); nine native CPython transcripts (`confirm-approve`, `confirm-deny`, `confirm-two`, `long-running`, `confirm-stale`, `confirm-incomplete`, `confirm-double-submit`, `confirm-consecutive`, `stream-confirm-approve`) reproduce on Pyodide in Node, and `confirm-approve` in real headless Chromium under the unchanged strict CSP (`tests/conformance/adk-python.node.test.ts`, `examples/rag-browser/test/adk-python-conformance.node.test.ts`). - Limits: the pause shapes decision 12 refuses were not exercised beyond the recorded native results; no real model, credential scan or device measurement exists.

Required before each feature flag turns on, and before this ADR is Accepted:

- `streaming`: checked text deltas in order and a mid-stream block that forwards nothing (stage AP3, observed above).
- `interrupts` and `resume`: confirmation and long-running pauses that resume by interaction ID, with stale and mismatched IDs failing before any tool runs (stage AP4, observed above).
- `checkpoints`: reload restore of a pending interaction, integrity-key tamper refusal and the frame-size guard, with the recovery guarantees of the other durable executors (stage AP5, observed above).
- A conformance lane of native CPython goldens reproduced on Node and Chromium, and a credential and content scan over logs, warnings, events, errors, spans and stored records (stage AP6, observed above).
