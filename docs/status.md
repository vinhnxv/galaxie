# Project status

This document records galaxie's implemented behavior, verification evidence and documented limits.

The repository is public. No legal review of learner data (minors, consent, retention) has been done, because the project has no legal counsel; see the [README](../README.md#intended-use-and-disclaimer) and [ADR-0024](adr/0024-apache-2-0-license-and-dco.md). The packages are not published to npm yet.

`@galaxie/ui-protocol` provides pinned A2UI v1.0 messages, strict parsing, catalog validation and a pure surface reducer. Core uses it for pending surfaces and React renders them (see the next paragraphs). It is verified by its own Node and Chromium tests, replayed upstream example messages and a conformance test that compares its URL check with core's. Nothing is measured about its cost on large surfaces. See the [package API and limits](../packages/ui-protocol/README.md).

Core accepts a surface-bearing interaction whose engine interrupt carries the reduced `galaxie.surface/1` record. It validates the record against a host-bound catalog and the URL and private-value policy over the whole surface before publication and on restore, checks the numeric revision and derived view token on dispatch, and adds `private-user` to changed model strings before acceptance. These paths are tested with fake executors and with the real LangGraph adapter over IndexedDB reload on Node and Chromium, using mock providers only. Not done: the interrupt cannot be replaced in place, so revisions advance per interaction; labels are not stored in the checkpoint (restore applies the conservative set); writable data paths are authorized by binding relation only; replayed submissions cannot recover the originating component; the tutor catalog export, an example agent that composes a multi-component surface and writable bindings are later work; nothing is measured about large surfaces. See [surface-bearing interactions](system-design.md#63-surface-bearing-interactions).

`@galaxie/react` renders materialized A2UI surfaces and normalizes today's single-component requests to a one-component surface, so the tutor, both templates and every example host keep working with their existing tests unchanged. Registered entries build the catalogs that `registry.bindings` hands to core; separate structural entries (Column, Row, Text, Card) compose surfaces; bindings are read-only; no renderer functions are evaluated. A later revision of the same surface updates in place and keeps component-local input and focus; a material change shows one fixed notice in a polite live region. This is a breaking change to the launch package's surface API, intended for a 0.x minor release. Verified with real core and fake executors in unit tests and Chromium conformance tests; no assistive-technology audit has been run and nothing is measured about large surfaces. The renderer's component cap uses core's default, not the run's configured budget; the change check compares whole component maps, so a reordered list counts as a change. Not done: the JSON Schema catalog export, an example agent composing several components, writable bindings and renderer functions.

The [local-only starter](../templates/local-only/README.md) supplies a standalone one-question LangGraph agent, an immediate deterministic mock when Built-in AI is unavailable, fixed model states and explicit size-disclosed WebLLM loading. It uses scoped IndexedDB checkpoints plus recovery and app ownership to restore a pending question. Node and Chromium tests are supplied for dependency/import boundaries, mock completion, unavailable/declined/failed/cancelled loading and restore, including a built-app reload test; they were not executed in the dependency-free implementation workspace. No real-device behavior, first download, latency or memory use is measured for this template. Packages remain unpublished.

The [hybrid-gateway starter](../templates/hybrid-gateway/README.md) supplies the identical one-question agent with a single host-server model route and a plain Node gateway. Server-side controls include five-minute scoped demo tokens, per-user call quotas, model allowlisting, validated prompt IDs and variables, bounded idempotency receipts and per-user fake document search. The page uses MemorySaver and fixed gateway statuses; reload starts over. Node and Chromium tests cover stub-upstream routing, validation, capability scoping, credential scans and a built-page flow over loopback in Node and headless Chromium. Span export is not exercised. Demo users and in-memory stores are not production authentication or storage; real upstream behavior, real-device results, latency and memory use are unverified and unmeasured. Packages remain unpublished.

A separate `demo` workflow builds the rag-browser example in mock mode with a demo flag (review checked by default, a one-line reload cue and a restored-review notice) and uploads the result as an artifact; it deploys nothing, and no demo host is chosen. The built page carries its policy as a meta element so it is enforced without response headers, and a `_headers` file holds the full policy for header-capable hosts. A meta policy omits `frame-ancestors` and does not cover Worker responses, so a header-less host has those protections missing; the maintainer must accept that limit before any deployment. A Chromium test serves the build from a header-less static server and checks enforcement, same-origin requests and paused-review restore after reload; it ran with the JavaScript executor only and uses mock models. Nothing is measured about the hosted page.

A separate `size` CI job builds the seven launch packages and compares each default JavaScript export against `scripts/size-budget.json`: every entry is bundled and minified alone with bare imports external, and own-code minified and gzip bytes must stay within the recorded limit (measured size plus 10 percent, rounded up to 100 bytes). A failure names the entry and the limit; entries without a budget line and stale budget lines also fail. The limits were generated from one macOS build with the pinned Vite and are regression guards only, not download sizes or device measurements; output determinism across platforms and bundler versions is not verified, so a first CI run may need the budget regenerated. Dependencies are excluded, so growth in a dependency is not caught.

No adapter exists for any of them. Import ownership and invalidation helpers from `@galaxie/core/browser`. Ownership protects local writes only when hosts compose `acquireOwnership({ appId, fence: saver.fencing, onHandoverRequest })` with runtime disposal. The lock is `galaxie:<appId>:runtime`; "Use here" requests cooperative handover before a timed forced takeover. A former host owner shows "The lesson moved to another tab." and disables input until reload. Epoch checks share each write's transaction and span every principal of the app. Reads remain available. Fencing does not protect against a tab that bypasses ownership; an already-sent remote request may complete, and a synchronous loop delays noticing loss. Backends can reject stale epochs when the host implements that protocol; galaxie sends no epoch headers. Node hosts need both Web Locks and `BroadcastChannel`. See [the ownership contract](system-design.md#85-tab-ownership-and-takeover).

Routing, labels, consent and model budgets apply only through `host.langchain.chatModel(role)`; trusted agent code holding its own model can bypass them (ADR-0002). The router's `maxTokens` is a reservation, so a call can use more and an actual-usage overrun fails the run only after that call returns. The lease now forwards the reservation as a per-call output limit through LangGraph, Pyodide and ADK JavaScript, with any supported lower caller or constructor limit preserved. WebLLM and Transformers keep their 1024 default; OpenAI-compatible calls omit the limit when neither a constructor nor a per-call value is supplied. Providers may overshoot; Built-in AI has no output-token limit, and the Go adapter is not covered. `getCredential` hands credentials to page code per call, where XSS or a malicious same-origin dependency can read them. Hosts should supply short-lived, host-proxy-scoped tokens rather than long-lived provider keys (ADR-0012).

`IndexedDBSaver.exportSession(sessionId, { personalContent? })` now adds principal-scoped session export with content-free defaults. Only exact `personalContent: true` includes decoded checkpoints and pending writes; hosts must bind that opt-in to an explicit user action and treat the result as personal data. Exports are frozen JSON snapshots with marked base64 bytes and fixed placeholders for unreadable values. Logout generation checks surround decoding; ownership loss leaves reads available. No storage schema, record format or database version changes. Chromium storage tests and the injected-fetch AT-23 scan cover exports through success, 401 and transport failure; pure conversion tests run on Node and Chromium. Host-local now binds metadata-only and confirmed personal-content downloads to explicit owner actions, with automated AT-19 evidence; no import, sync or cross-device recovery ships. See [export semantics](../packages/storage-indexeddb/README.md#explicit-session-export).

`packages/adapter-adk` (`adk-js`) now hosts Google ADK 2.3.0 agents from its web bundle under the unchanged strict CSP and Trusted Types, with the adapter owning the Runner, router-backed models and capability-backed tools. It supports `LlmAgent`, `SequentialAgent`, `ParallelAgent` and `LoopAgent` trees, checked streaming, confirmations and long-running tools as interactions, and durable sessions through the byte-record port with reload restore. `subgraphs` is false, and a pause is refused where ADK would restart earlier siblings. Evidence is Node and headless Chromium with scripted models, native-versus-galaxie goldens and no real model; ADR-0020 is Proposed. Decision model roles are accepted in [ADR-0028](adr/0028-decision-model-role.md) for the contract, the structured-output provider and the confidence gate, with no dedicated model chosen, and partly built: core has a `decision` modality that routes only to decision providers with the text roles' lease, consent, label, budget and output-check path, validators for 1–16 boolean, choice and score questions and their answers, `host.langchain.decide` in the LangGraph adapter, a scripted `MockDecisionModel`, a structured-output provider (`@galaxie/models/decision`) that turns any routed chat model with structured output into a decision provider and reports generated tokens but never confidence or probabilities, and bounded repair of invalid answers (each repair is a separately leased attempt within the route's `repairAttempts` and the shared run repair allowance; exhausting it fails with the fixed `invalid` error). Verified with mocks and fake engines only, in unit tests and a real runtime; nothing was run in Chromium for this path and no real model has answered a decision. Because the structured-output provider reports no confidence, a gate over it always asks. Four corpus cases drive an obedient decision mock to demand skipped confirmations (including a valid high-confidence answer); the host confirmation is still published in each, on Node and in Chromium.
